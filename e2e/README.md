# 전과정 자동 테스트(e2e) 하네스

모의 서버 위에서 테스트봇으로 웹 수강신청을 넣고, 앱을 **사용자처럼 클릭**해 1→5단계를 진행하며 결과를 점검합니다.
실제 Supabase 서버에는 요청하지 않습니다(가로채지 못한 외부 요청은 막고 `report.json`의 `blockedRequests`에 남김).

```
npm ci                                   # @electric-sql/pglite (모의 서버)
node e2e/run.cjs --seed 1 --out /tmp/e2e-seed1
```
- Playwright·Chromium은 이 환경에 전역 설치된 것을 씁니다(하네스가 `npm root -g`에서 찾음).
- 옵션: `--seed n`(같은 시드 = 같은 결과) · 학년별 명단 `--classes1 10 --perClass1 34 --classes2 11 --perClass2 28`(기본값, 사용자 학교: 현1 10학급 → 내년 11학급) · `--nextClasses 11`(4·5·6단계 내년 학급 수) · `--classes`/`--perClass`(두 학년 같이) · `--concurrency 1`(봇 동시 접속, 1이어야 시드 재현) · `--stopAfter 1|2|3|4` · `--headed` · `--explore 파일.cjs`(2단계 뒤 탐색 스크립트).
- 결과: `--out` 폴더에 `report.json`(단계별 통과/실패·문제 목록·시간·모의 서버 기록 요약·콘솔), 단계별 스크린샷, `downloads/`(코드·집계표·시수 엑셀·백업 JSON·봇 결과), 합성 편제표·명렬 엑셀. 가상 학생만 씁니다.

## 추가 시나리오(2차)
- **학생 화면 직접 신청**: 봇은 1~(반수−1)반만 돌리고, 마지막 반은 하네스가 학생 화면(`#event=`)으로 직접 로그인·코드 변경·학기별 체크·저장. 5%는 위반 선택(현1: 물리학 없이 역학과 에너지 / 현2: 중국어 → 일본어 회화 + 국·수·영 최대로 국수영 초과), 나머지는 정상, 3명은 미제출.
- **하네스 기대값**(`lib/expected.cjs`, 앱 함수 미사용): 합성 편제표 + 해당 기본 위계 규칙으로 학생별 위계 미충족·확인 불가·학기 학점 부족·국수영 초과를 계산해 2단계 점검 팝업 · 3단계 '위계 경고만'·위반 학생 확인서 점검란 · 4단계 학년 칩과 대조.
- **나이스 가상 자료**(`lib/neis-fixture.cjs`): 현2의 2026학년도 1·2학기 이수 기록(가린 이름 '김00') + 연결되지 않는 2025 기록. 점검 팝업 '이전 학년 이수 결과'에 올려 연결 수·확인 불가 0·위계 경고 기대값 대조.
- 합성 편제표 예술 10학점(음악 3+3 + 교차집중 미술↔연극), 정보 1+1(총 174 유지).
- **6단계 분반 편성**(`lib/step6.cjs`·`lib/step6-scenario.cjs`, 메뉴 `6. 분반 편성`): 1차 확정 전 시안 편성·확정 뒤 표시 → 5단계 교과별 교사 수 입력 → 2차 확정 결과로 `교사·시간 설정`(5단계 교사 수로 명단 + 육아시간·순회 가상 교사 불가 시간 + 창체 금6·7) → 첫 그룹 `방식 비교·추천`(배정표 없을 때 담임반 묶기 '추천 제외' 확인) → 추천 방식 → 학기마다 `블록 시간 추천` → `추천 적용` → `전 학년 함께 다시 계산` → 내년 반 배정표(현1 10→11 섞음, 현2 11→11 그대로) 올림·나이스 반·번호 대조 → 불가면 `제안 적용`(최대 3번) → 3학년 택1 `학급 단위` → 그룹별 블록표·분반 명렬표·나이스 엑셀을 직접 읽어 검증(미배정·블록 충돌·정원·강의실 이름 규칙·나이스 머리글/한 줄/명렬표 일치, 그룹 간 학생·교사 같은 시간·불가 시간·창체) → 2차 확정 해제·교사 화면으로 3명 변경·재확정·`바뀐 학생만 다시 계산`(나머지 학생 분반 유지 대조) → 새로고침·백업 복원 뒤 6단계 같음.
- **6단계 예전 자리**(`stepTimetable`, `lib/timetable-checks.cjs`): 메뉴가 '보류'면 건너뜀. 들어오면 `STEP6` 단추 이름과 화면 읽기(adapter)만 맞추면 미배정·블록 충돌·정원·교사 불가/중복·나이스 내보내기(열 구성·학생·과목당 한 줄·최종 선택과 일치)를 검사. `node e2e/selftest.cjs`로 순수 함수 점검.
- 환경 주의: 이 Chromium은 한글 파일 이름을 고르면 선택이 취소되고(파일 입력에 안 들어감), 내려받기 이름이 'download'로 와서 하네스가 영문 이름·내용으로 구분한다(앱 문제 아님).

- **두 학기 편성 과목 개설 학기·단계 간 일치**(2-7, `lib/two-semester-scenario.cjs`·`lib/two-semester-fixture.cjs`): 저장 단계 뒤 새 차수에 현2 가로형 결과(심화 영어 한 열, 학기 경계) → 미리보기 '개설 학기 선택'(고르지 않고 반영 → '개설 학기 확인' 창 → 돌아가서 고르기) 2학기 → 섞지 않고 한 줄 → 4단계 그 학기 구역에만 → 확정 → 5단계 시수표 칸 = 6단계 분반 수 = 4단계 → 확정 해제·과목 메뉴 '개설 학기 바꾸기' 1학기 → 다시 확정 → 따라감 → 다음 차수에 같은 파일(앞 차수 결과로 추천) → 머리글 '3-2 택5' 병합 파일(묻지 않음). 단독 실행: `node e2e/two-semester-consistency-ui.cjs <폴더> <백업.json.gz> [--diagnose]`.

## 구성
- `lib/mock-supabase.cjs` — `supabase/*.sql` 체인 + `proposed/01·02`(앱이 쓰는 학생 잠금 RPC)를 PGlite에 올리고 Playwright `context.route`로 RPC·REST(`course_events` 목록)·auth(구글 PKCE 흉내: authorize → `?code=` 되돌림 → token)를 처리. 실시간 websocket은 닫음(앱은 30초 동기화로 넘어감).
- `lib/static-server.cjs` — 저장소를 `http://127.0.0.1`로 제공(file://는 앱이 오프라인으로 봄).
- `lib/plan-fixture.cjs` — 합성 2022 개정 편제표(학교 지정 + 2학년 학기별 택3·택1, 3학년 학기별 택5·택1, 교차집중 미술↔연극). 연도만 바꿔 2026·2025 입학생에 씀.
- `lib/harness.cjs` — 브라우저·기록·스크린샷. 테스트봇은 `Date.now()`로 난수 시드를 정하므로 하네스가 페이지에서 `TestBotCore.createRng`를 감싸 시드를 고정합니다(앱 코드는 그대로).
- `run.cjs` — 시나리오: 로그인 → 편제표 업로드 → 웹 방식·그룹 확인 → 학년별 명렬 업로드·신청 생성(자동 연동) → 테스트봇(인기 편중·틀린 코드 4%·위반 시도 10%·재제출 10%) → 마감 → 3단계 확인서 표본 대조 → 4단계 기준(11학급·34명)·집계=서버 대조·개설/폐강·자동 조정·엑셀·1차 확정 → 폐강 학생 재신청(2차, 대상 학생만)·봇 → 2차 집계·확정 → 2차 확인서 → 5단계 시수 설정·표·엑셀 → 새로고침·백업→전체 초기화→복원 비교·저장 용량.
