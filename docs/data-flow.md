# 자료 연결 지도 — 과목 신원과 개설 학급 수가 단계 사이를 어떻게 지나가는가

이 문서는 "4단계 집계와 5단계 시수 통계가 다르게 보인다"는 문제를 계기로 만들었습니다(2026-11). 편제표에서 6단계 출력물까지, 단계마다 **무엇을 읽는지**, **과목을 무엇으로 맞추는지**(이름·키·학기), **어디서 다시 계산하는지**를 적습니다. 코드를 바꿀 때 이 표와 `tests/data-consistency.test.cjs`를 함께 고치세요.

## 한 줄 요약

```
1단계 편제표 데이터 ─▶ collectApplicationSubjects ─▶ 2단계 선택 그룹(getApplicationGroupSettings)
                                   │                           │
                                   ▼                           ▼
                      2단계 결과 취합(createRecords / mergeApplications → classifyApplicationRecords
                                     · splitUntaggedTwoSemesterCourses · 개설 학기 선택 courseSemesterPicks)
                                   │  state.rounds[차수] = { students, courses, classOverrides, … }
                                   ▼
          4단계 aggregateRecords(학기·그룹·과목 → 인원·권장/입력 학급수·폐강) = 화면 집계표·엑셀
                                   │  buildRoundSnapshot(같은 aggregateRecords를 행 목록으로)
                                   ▼
        ★ 과목 개설 결정의 한 출처: courseOpeningRound(현학년) + courseOpeningSnapshot(차수)   (round-status.js)
              확정된 차수 = 확정 스냅샷 · 아니면 지금 4단계 기준 스냅샷(캐시)
                 │                                         │
                 ▼                                         ▼
     5단계 computeHoursStats 개설반 자동 값          6단계 classSectionsSource 분반 수(그룹 = 현학년:학기:택n)
     (편제표 학기 칸 × 4단계 학급 수)                  (학생 명단은 같은 차수 자료, 학급 수는 스냅샷)
```

## 개설 학기 정하기(사용자 규칙)

편제표 1·2학기에 모두 편성된 과목은 세 경우입니다: ① 1·2학기 동시 개설 ② 1학기만 개설 ③ 2학기만 개설. 결과 파일(차수마다)에서 이렇게 정합니다.

1. **머리글 표시가 먼저**: 과목 이름 줄 위 칸(병합 머리글이면 병합 범위 첫 칸 글자)의 '2학기'·'3-2 택5'·'3학년 2학기', 없으면 시트 이름('3학년 2학기 결과'처럼 학년이 있을 때만). 학년이 적혀 있으면 신청 학년과 같을 때만 쓰고, 과목 열 전체를 덮는 제목 칸은 보지 않습니다(`applyResultHeaderHints`). 표시로 정해지면 **묻지 않고** 미리보기에 근거만('머리글 표시 '3-2 택5' → 2학기').
2. **같은 이름 두 열 = 동시 개설**: 왼쪽 열 1학기·오른쪽 열 2학기, 학생은 자기가 체크한 열의 학기(`labelRepeatedCourseColumns`). 미리보기 근거 '위치로 정함: 왼쪽 열 → 1학기'. 목록형(한 칸에 쉼표)은 한 학생 안에서 두 번이면 앞 1학기·뒤 2학기(`mergeApplications`).
3. **한 번만 나옴 = 한 학기만 개설 → 교사가 고름**: 미리보기 '두 학기 편성 과목 — 개설 학기 선택'(과목마다 1·2학기, 추천값과 추천 근거). 고른 학기로 그 과목 학생 **전부**를 고정합니다(학생별로 섞지 않음). 고르기 전에 반영하면 '개설 학기 확인' 창('돌아가서 고르기'/'추천한 학기로 반영' — 반영하면 추천값을 고른 값으로 저장).
   - 추천 순서: 앞 차수 4단계 결과(그 과목을 폐강한 학기 → 한 학기만 개설했으면 그 학기, `courseSemesterPreviousRecommendation`) → 이웃 열 학기 → 학생별 택n 추정 다수 → 1학기. 추천은 표시·기본 선택일 뿐 자동 확정하지 않습니다.
   - **차수마다 따로**: 재신청 차수 파일은 동시 개설 과목도 한 학기분만 나올 수 있으므로 저장 키에 차수가 있고, 앞 차수에 고른 값을 그대로 쓰지 않습니다.
4. 웹 신청 결과는 학생이 학기를 골라 신청하므로(과목명 'X (n학기)') 고르지 않습니다. 한 학기만 열었으면 5단계가 다른 학기를 '두 학기 편성 · n학기만 개설'로 0.

- 저장: `state.courseSemesterPicks[학년도][현학년][차수][courseSemesterPickKey(과목명)] = "1" | "2"`(백업·IndexedDB 조각·전체 초기화 포함). 복원 `courseSemesterPicksRestore(saved.courseSemesterPicks, saved.twoSemesterPicks)`: 차수 없는 예전 키와, 같은 기능을 먼저 만든 다른 구현(07d151c)의 `state.twoSemesterPicks`는 1차 값으로 옮깁니다(그 구현의 `switchTwoSemesterCourse`·미리보기 표·`data-two-semester-once`는 이 구현으로 합치며 지움).
- 바꾸기: 4단계 과목 메뉴 `개설 학기 바꾸기 · N학년 1학기로 / 2학기로`(확정 잠금 따름, 확인 창) → 이 차수 고른 값 저장 → `applyTwoSemesterPick`(열 그대로 이름·학점·학기 표시를 바꾸고, 나뉜 열이 있으면 한 열로) → `classifyApplicationRecords`로 그룹 다시 정함 → 4·5·6단계·확인서·위계 점검이 같은 자료를 읽어 따라감. 그 과목의 학급수 입력·개설 결정은 지웁니다(학기가 바뀌므로).
- 하지 않는 것(사용자 결정): 고른 학기로 택n 개수를 검사하는 기능(잘못 고르면 4단계 학년별 총 학급수 불일치로 드러남), 레이블 하나 과목을 두 학기로 나눠 여는 경우(그때는 편제표를 고침).

## 남긴 것

- 앞 차수 설정 이어받기(`storeGradeResults`·`effectiveRoundClosures`)는 이름 + 학기 기준 그대로입니다. 인원이 크게 바뀐 과목에 앞 차수 학급수가 이어질 수 있으나 4단계에 보이고 고칠 수 있어 그대로 두었습니다.
- 4단계 화면은 확정된 차수도 지금 자료로 계산해 그립니다(스냅샷으로 그리지 않음). 대신 둘이 다르면 알립니다.
- 5단계 '근거 차수 고정'(`settings.sourceRounds`)은 사용자가 고른 것이므로 한 출처 규칙보다 우선합니다.
