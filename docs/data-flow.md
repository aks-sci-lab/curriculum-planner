# 자료 연결 지도 — 과목 신원과 개설 학급 수가 단계 사이를 어떻게 지나가는가

이 문서는 "4단계 집계와 5단계 시수 통계가 다르게 보인다"는 문제를 계기로 만들었습니다(2026-11). 편제표에서 6단계 출력물까지, 단계마다 **무엇을 읽는지**, **과목을 무엇으로 맞추는지**(이름·키·학기), **어디서 다시 계산하는지**를 적습니다. 코드를 바꿀 때 이 표와 `tests/data-consistency.test.cjs`를 함께 고치세요.

## 한 줄 요약

```
1단계 편제표 데이터 ─▶ collectApplicationSubjects ─▶ 2단계 선택 그룹(getApplicationGroupSettings)
                                   │                           │
                                   ▼                           ▼
                      2단계 결과 취합(createRecords / mergeApplications → classifyApplicationRecords
                                     · splitUntaggedTwoSemesterCourses · 개설 학기 선택 courseSemesterPicks)
                                   │  state.rounds[차수] = { students, courses, classOverrides, … }
                                   ▼
          4단계 aggregateRecords(학기·그룹·과목 → 인원·권장/입력 학급수·폐강) = 화면 집계표·엑셀
                                   │  buildRoundSnapshot(같은 aggregateRecords를 행 목록으로)
                                   ▼
        ★ 과목 개설 결정의 한 출처: courseOpeningRound(현학년) + courseOpeningSnapshot(차수)   (round-status.js)
              확정된 차수 = 확정 스냅샷 · 아니면 지금 4단계 기준 스냅샷(캐시)
                 │                                         │
                 ▼                                         ▼
     5단계 computeHoursStats 개설반 자동 값          6단계 classSectionsSource 분반 수(그룹 = 현학년:학기:택n)
     (편제표 학기 칸 × 4단계 학급 수)                  (학생 명단은 같은 차수 자료, 학급 수는 스냅샷)
```

## 과목 신원(같은 과목인지 맞추는 기준)

## 단계별 표

| 단계 | 읽는 것 | 과목 맞추기 | 개설 학급 수 출처 | 다시 계산하는 곳 |
|---|---|---|---|---|
| 1 편제표 | 업로드 원본 → `planData` | 과목 한 행 | — | `curriculumPlanEntries`(5단계용 학기 항목), `collectApplicationSubjects`(신청 과목: 두 학기면 `semester: "1·2"`, `sameCourseOnce`) |
| 2 선택 그룹 | 편제표 묶음(`curriculumPlanGroupAssignments`) | 그룹 과목명 | — | `getApplicationGroupSettings()`(약 50ms, 반복 안에서 부르지 말 것) |
| 2 결과 취합 | 결과 파일 | 열 + 이름 | — | `classifyApplicationRecords` = 두 학기 과목 나누기(`splitUntaggedTwoSemesterCourses`, **저장된 개설 학기가 있으면 그 과목 학생 전부 그 학기**) → 그룹 정하기. 반영 때 `storeGradeResults`가 열 번호를 바꾸고 같은 차수 안의 설정을 **이름 + 학기**로 옮김(앞 차수 설정은 새 차수를 만들 때 복사) |
| 3 확인서·위계 점검 | `state.students[].selections`(`applicationSelections`) | 선택의 이름·`semesterKey` | — | 저장 자료 그대로(개설 학기를 바꾸면 선택 자체가 바뀌므로 따라감) |
| 4 집계 | 지금 차수 `students`·`courses`·`classOverrides`·폐강(`roundClosures[차수]`, 새 차수를 만들 때 직전 차수에서 복사 · `effectiveRoundClosures`는 이름만 남음)·내년 학급 수 | 열 | 입력값(`classOverrides`) 또는 권장값(인원 ÷ 분반 기준), 폐강이면 0 | `aggregateRecords` 하나(화면·엑셀·스냅샷·학급수 자동 조정이 함께 씀) |
| 차수 확정 | `buildRoundSnapshot` = 같은 `aggregateRecords` | 행 = 현학년·학기·그룹·`subjectName` | 확정 시점 `classCount` | 확정하면 고정. 확정 뒤 자료와 달라지면 `roundSnapshotStale`이 과목을 알려 줌 |
| **한 출처** | `courseOpeningRound()` = **맨 위에서 고른 차수**(`state.currentRound`, 아래 '차수별 흐름' 참고) | — | `courseOpeningSnapshot(차수)`: 확정 스냅샷 또는 지금 4단계 기준 스냅샷(`cachedByStateRevision`) | — |
| 5 시수 | 편제표 학기 항목(학점) + 한 출처 스냅샷 행 | `정규화 이름` + 학기 | 같은 학기 행의 `classCount` 합. **두 학기 편성 과목**: 다른 학기에만 행이 있으면 이 학기 0(근거 '두 학기 편성 · n학기만 개설'), 학기 미정 행은 어느 학기에도 넣지 않고 경고(4단계에서 학기 정하기). **2·3학년 선택과목은 4단계 연동**(시수표 칸은 값 단추 → 누르면 4단계 그 과목 칸 `focusAggregateCourse`, 예전 직접 입력 `classOverrides`는 지우지 않고 무시 + 참고 안내 '4단계와 다른 직접 입력 n개를 4단계 값으로 바꿨습니다'), 4단계 집계에 없는 선택과목만 직접 입력('4단계에 없는 과목 · 직접 입력'). **학교 지정 과목은 편제표 × 내년 학급 수 연동**(`hoursDesignatedShare`: 분할 편성·교차집중 홀수 학급 `crossExtra`; 값 단추 → 시수 설정 학급 수 칸, 교차집중 홀수는 1단계 편제표; 예전 직접 입력은 무시 + '편제표와 다른 직접 입력 n개를 편제표 값으로 바꿨습니다'). 단 **확대학급**(수준별 이동수업, 시수 설정 체크 `expandedClassesOn`을 켰을 때만): 과목별 상세의 확대 값 `expandedClasses[과목 키]`이 편제표 값보다 크면 그 값(작아지면 쓰지 않고 경고, 끄면 저장만), **5단계 시수에만 반영 · 6단계 분반은 그대로**. 1학년 선택과목만 직접 입력 | `computeHoursStats`(`hoursStatsCached`) |
| 6 분반 | 같은 차수 자료(학생 명단) + 확정 스냅샷 학급 수 | 그룹 키 `현학년:학기:택n`, 과목 키 `subjectName` | 스냅샷 `classCount`(없으면 지금 4단계), 6단계 직접 입력은 '4단계와 다름' 표시 | `classSectionsSource`(차수 = 맨 위 차수, 6단계 차수 선택 상자 없음) |

## 찾은 불일치와 고친 곳

재현: `e2e/lib/two-semester-fixture.cjs`(현 2학년 11학급 × 28명, 성명 '학생n'), `심화 영어`(편제표 3-1 택5·3-2 택5에 모두)를 가로형 결과에 **한 열**로, 3-1 과목과 3-2 과목 사이(학기 경계)에 둠. 179명 신청 중 12명은 3-1에서 4과목만(=1학기로 추정), 167명은 3-2에서 4과목만(=2학기로 추정). 하네스 seed 10 백업 위 3차로 올림.

| # | 증상(예전 코드) | 원인 | 고친 곳 |
|---|---|---|---|
| 1 | 한 학기만 개설한 과목이 4단계에 1학기·2학기 두 줄로 나뉨(1학기 12명, 2학기 167명) | 학기 경계 열이면 학생별 택n 추정 → 학생마다 다른 학기 | 한 번만 나온 과목은 학생별로 섞지 않고 한 학기(교사가 고른 학기, 고르기 전엔 추천값)로 전부 고정 + 미리보기 **'두 학기 편성 과목 — 개설 학기 선택'**(추천·근거, 고르지 않고 반영하면 확인 창), 머리글 표시가 있으면 묻지 않음(아래 '개설 학기 정하기') |

## 차수별 흐름(사용자 결정 2026-11)

맨 위 '결과 차수'(`#workspaceRound`) 하나가 2~6단계 모든 화면의 기준입니다. 숨은 차수 고르기 규칙은 없습니다(round-copy.js · round-status.js).

| 차수마다 따로 | 전체에 하나 |
|---|---|
| 신청 결과(학년별) `rounds[r]`, 4단계 개설·폐강 `roundClosures[r]`·학급수 입력 `rounds[r].classOverrides`, 확정·스냅샷 `roundStatuses[r]`, 6단계 분반 결과·고정 `classSections[r]`, 고른 개설 학기 `courseSemesterPicks[연][학년][r]`, 학년마다 출처 `rounds[r].gradeSources[학년]` | 편제표, 선택 그룹, 4단계 기준(%) · 내년 학급 수, 5단계 시수 설정(교사 수·나누기·창체), 6단계 settings(교사·교실·불가 시간) |

- **새 차수 = 직전 차수 복사**(`addApplicationRound`): 두 학년 결과·개설/폐강·학급수 입력·6단계 분반(확정·고른 개설 학기는 복사하지 않음). `gradeSources[학년] = { kind: "copy", round, from: { round, signature } }`. 결과를 올린 학년만 바뀝니다. 앞 차수 '이어받기'(`effectiveRoundClosures`의 이름 맞추기·`priorRoundSettings`)는 없앴습니다.
- **결과 올리기 방식**(결과 검증 미리보기 `#resultImportMode`): '학년 전원 파일'(그 학년 통째로) / '재신청한 학생만 있는 파일'(학년·반·번호로 맞춰 파일 학생만 바꿈, 없던 학생은 추가, '바뀌는 학생 n명 · 그대로 m명 · 추가 k명(전입 등)', `roundMergeGradeStudents`). 과목 열은 같은 이름·학기(`roundCourseIdentity`).
- **웹 결과**(`applyCloudApplicationResults`): 웹 결과가 없는 학년은 지우지 않음(그 차수 몫 → 없으면 직전 차수 복사). 웹 과목 열 번호가 밀려도 개설 결정·학급수 입력은 이름·학기·그룹으로 새 열에(`roundRemapKeysByName`).
- **근거 한 줄**(5·6단계 맨 위, `roundBasisHtml`): '근거: 3차 · 현1: 3차 결과(확정) · 현2: 2차에서 복사(미확정)'. 복사한 학년의 앞 차수가 복사 뒤 바뀌면(서명 비교) '2차가 복사 뒤 바뀜 · 이 학년 다시 복사'(확인 창, 저절로 다시 복사하지 않음). 미확정이어도 그 차수 4단계 값으로 계산합니다.
- **예전 자료 옮기기**(열 때 한 번, `migrateRoundGrades`): 학년이 비어 있는 차수는 직전 차수에서 복사하고 안내('3차에 현2 결과가 없어 2차 결과를 복사했습니다'). 일부 학생만 있으면(직전 차수의 절반 미만 · 모두 직전 차수 학생) 확인 창 '차수 결과 합치기'(합치기 / 그대로 두기), 고른 값은 `gradeSources[학년].decided`로 다시 묻지 않음. 확정 차수는 건드리지 않음.
- 없앤 것: 5단계 '선택과목 근거' 칸(`settings.sourceRounds`는 저장돼 있어도 읽지 않음), 6단계 `#classSectionsRound`, 4단계 '5·6단계는 다른 차수…' 안내, 5단계 '임시 계산' 경고.

## 개설 학기 정하기(사용자 규칙)

편제표 1·2학기에 모두 편성된 과목은 세 경우입니다: ① 1·2학기 동시 개설 ② 1학기만 개설 ③ 2학기만 개설. 결과 파일(차수마다)에서 이렇게 정합니다.

1. **머리글 표시가 먼저**: 과목 이름 줄 위 칸(병합 머리글이면 병합 범위 첫 칸 글자)의 '2학기'·'3-2 택5'·'3학년 2학기', 없으면 시트 이름('3학년 2학기 결과'처럼 학년이 있을 때만). 학년이 적혀 있으면 신청 학년과 같을 때만 쓰고, 과목 열 전체를 덮는 제목 칸은 보지 않습니다(`applyResultHeaderHints`). 표시로 정해지면 **묻지 않고** 미리보기에 근거만('머리글 표시 '3-2 택5' → 2학기').
2. **같은 이름 두 열 = 동시 개설**: 왼쪽 열 1학기·오른쪽 열 2학기, 학생은 자기가 체크한 열의 학기(`labelRepeatedCourseColumns`). 미리보기 근거 '위치로 정함: 왼쪽 열 → 1학기'. 목록형(한 칸에 쉼표)은 한 학생 안에서 두 번이면 앞 1학기·뒤 2학기(`mergeApplications`).
3. **한 번만 나옴 = 한 학기만 개설 → 교사가 고름**: 미리보기 '두 학기 편성 과목 — 개설 학기 선택'(과목마다 1·2학기, 추천값과 추천 근거). 고른 학기로 그 과목 학생 **전부**를 고정합니다(학생별로 섞지 않음). 고르기 전에 반영하면 '개설 학기 확인' 창('돌아가서 고르기'/'추천한 학기로 반영' — 반영하면 추천값을 고른 값으로 저장).
   - 추천 순서: 앞 차수 4단계 결과(그 과목을 폐강한 학기 → 한 학기만 개설했으면 그 학기, `courseSemesterPreviousRecommendation`) → 이웃 열 학기 → 학생별 택n 추정 다수 → 1학기. 추천은 표시·기본 선택일 뿐 자동 확정하지 않습니다.
   - **차수마다 따로**: 재신청 차수 파일은 동시 개설 과목도 한 학기분만 나올 수 있으므로 저장 키에 차수가 있고, 앞 차수에 고른 값을 그대로 쓰지 않습니다(새 차수 복사에도 넣지 않음).
4. 웹 신청 결과는 학생이 학기를 골라 신청하므로(과목명 'X (n학기)') 고르지 않습니다. 한 학기만 열었으면 5단계가 다른 학기를 '두 학기 편성 · n학기만 개설'로 0.

- 저장: `state.courseSemesterPicks[학년도][현학년][차수][courseSemesterPickKey(과목명)] = "1" | "2"`(백업·IndexedDB 조각·전체 초기화 포함). 복원 `courseSemesterPicksRestore(saved.courseSemesterPicks, saved.twoSemesterPicks)`: 차수 없는 예전 키와, 같은 기능을 먼저 만든 다른 구현(07d151c)의 `state.twoSemesterPicks`는 1차 값으로 옮깁니다(그 구현의 `switchTwoSemesterCourse`·미리보기 표·`data-two-semester-once`는 이 구현으로 합치며 지움).
- 바꾸기: 4단계 과목 메뉴 `개설 학기 바꾸기 · N학년 1학기로 / 2학기로`(확정 잠금 따름, 확인 창) → 이 차수 고른 값 저장 → `applyTwoSemesterPick`(열 그대로 이름·학점·학기 표시를 바꾸고, 나뉜 열이 있으면 한 열로) → `classifyApplicationRecords`로 그룹 다시 정함 → 4·5·6단계·확인서·위계 점검이 같은 자료를 읽어 따라감. 그 과목의 학급수 입력·개설 결정은 지웁니다(학기가 바뀌므로).
- 하지 않는 것(사용자 결정): 고른 학기로 택n 개수를 검사하는 기능(잘못 고르면 4단계 학년별 총 학급수 불일치로 드러남), 레이블 하나 과목을 두 학기로 나눠 여는 경우(그때는 편제표를 고침).

## 7단계 시간표(구현 중)
- 설계 `docs/timetable-design.md`. 지금 있는 것은 순수 계산뿐(`timetable.js`: 입력 모형 `timetableModel` + 사전 점검 `timetablePrecheck`). **앱 자료를 읽는 연결(`timetableInput`)은 아직 없다** — 화면 걸음(T3)에서 5단계 `computeHoursStats` 항목(과목·학점·반 수·공통 과목 배분)과 6단계 `sectionResult`(블록·분반·분반 교사)·`settings.teachers`를 읽기 전용으로 모으고, 같은 값을 다시 입력받지 않는다. 그때 이 표에 '7 시간표' 줄과 '5단계 시수 합 = 7단계 교사 시수 합' 검사를 더한다.
- 6단계 '시간표 미리 점검'(`sectionResult.timetableCheck`)의 규칙은 `timetable.js` `timetablePrecheckDepartments` 한 곳(6단계 화면은 부르기만).

## 남긴 것

- 4단계 화면·집계표 엑셀은 확정된 차수도 지금 자료로 계산해 그립니다(스냅샷으로 그리지 않음). 5·6단계는 확정 스냅샷을 쓰므로 둘이 다르면 `roundSnapshotStale`이 알립니다('확정 해제 후 다시 확정').
- 예전 저장 자료의 `settings.sourceRounds`(5단계 '선택과목 근거')·5단계 `classOverrides`(2·3학년 선택과목)는 지우지 않고 읽지 않습니다.
- 웹 재신청 생성(`retakeClosedSubjects`, supabase-client.js)은 교사가 고른 앞 신청(event)의 차수 결정을 씁니다(그 차수 하나 · 이름으로 모으지 않음).
