수강신청 테스트봇

가상 학생으로 웹 수강신청을 시험하거나, 2단계에 올릴 가상 수강신청 결과 엑셀을 만듭니다.

1. 대상 수강신청과 학생 코드

실제 서버의 수강신청에 가상 신청이 저장됩니다. 테스트용으로 만든 수강신청에만 쓰고, 실제 학생 신청에는 쓰지 마세요.

앱 교사 화면(2단계 → 온라인 신청 관리)의 ‘테스트봇으로 보내기’ 또는 ‘수강신청 자동 테스트’로 열면 학생 코드가 이 창으로 바로 들어옵니다.

직접 넣기: 학생 신청 링크 + 학생별_신청코드.xlsx

2. 실행 설정

기본(꺼짐): 수강신청은 그대로 두고 2회차부터 가상 학생이 바뀐 코드로 다시 접속해 새 선택으로 재신청합니다. 켜면(앱의 ‘수강신청 자동 테스트’로 시작할 때만) 회차마다 [테스트] 신청을 새로 만들고 회차가 끝나면 닫고 삭제합니다. 켜면 테스트 결과가 교사의 실제 작업 자료(해당 차수)에 들어갑니다. 백업 후에만 쓰세요.

설정은 이 브라우저에 저장되어 ‘수강신청 자동 테스트’에도 쓰입니다. 학생 코드는 저장하지 않습니다.

3. 실행과 결과

대기 중

단계

    회차학생상태바뀐 코드선택 과목관찰실패 사유

    1. 앱 설정 읽기

    같은 브라우저에 저장된 앱 자료(편제표·2단계 선택 그룹)를 읽기만 합니다. 먼저 앱에서 해당 입학연도 편제표를 올리고 2단계 학년 탭의 그룹을 확인하세요.

    2. 학생과 선택

    일부러 넣을 오류

    3. 파일 형식과 만들기

    형식

    학년 열은 현재 학년(현 1학년 학생은 2학년 과목 신청)으로 적습니다. 목록 형식에서 편제표에 없는 과목은 앱이 ‘반영할 수 없는 오류’로 막습니다.

    실제 서버에 가상 신청을 저장합니다

    실제 서버의 이 수강신청에 가상 신청이 저장됩니다. 실제 학생 신청에는 쓰지 마세요.

    테스트 수강신청 정리

    테스트가 끝났습니다. 앱이 만든 [테스트] 수강신청을 어떻게 할까요?

    수강신청 테스트봇 사용 안내

    • 가장 쉬운 방법: 앱 2단계 → 온라인 신청 관리에서 구글 로그인 후 수강신청 자동 테스트를 누르세요. 가상 학생으로 [테스트] 수강신청을 만들고, 이 창이 접속·첫 코드 변경·과목 선택·저장 확인·교사 화면 대조·정리(기본: 닫기만)까지 자동으로 진행합니다.
    • 반복 횟수: 1~20회. 기본은 테스트 수강신청을 한 번만 만들고, 2회차부터 가상 학생이 바뀐 코드로 다시 접속해 새 무작위 선택으로 재신청합니다. 틀린 코드(잠금 확인)는 1회차에만 넣고, 잠긴 학생은 다음 회차 전에 교사 화면 경로로 잠금을 풀어 다시 참여시킵니다. 회차마다 교사 화면(신청 현황·과목별 인원·잠금)과 대조하고, 회차별 표와 회차 사이 변화를 화면·엑셀로 남깁니다. ‘회차마다 새 수강신청 만들기’를 켜면 회차마다 신청을 새로 만들고 닫고 삭제합니다. 반복이 길어져도 앱 창의 교사 로그인을 이어 두며, 로그인이 끝나면 멈췄다가 앱 창에서 다시 로그인하면 이어서 진행합니다.
    • 이미 만든 테스트 신청: 앱에서 코드를 만든 뒤 테스트봇으로 보내기를 누르거나, 학생 신청 링크와 학생별_신청코드.xlsx를 ‘직접 넣기’에 넣고 실행을 누르세요. 확인 창에 ‘테스트’를 입력해야 시작합니다.
    • 가상 학생은 그룹마다 정확히 정해진 수만큼, 1·2학기 같은 과목을 겹치지 않게 무작위로 고릅니다. 오류 주입(틀린 코드, 규칙 위반, 재신청)은 서버가 막는지 확인하는 용도입니다. 규칙 위반 학생 중 위계(선이수)를 어긴 선택은 경고만이라 저장되는 것이 정상입니다(‘위계 경고 저장’). 첫 접속에서 바뀐 코드는 결과표·엑셀에만 남습니다.
    • 결과 파일 만들기(로컬): 서버 없이 앱 2단계 ‘결과’ 탭에 올릴 가상 결과 엑셀을 만듭니다. 같은 브라우저의 앱 편제표·선택 그룹을 읽기만 하며, 일부러 오류를 넣어 앱 경고를 확인할 수 있습니다.
    • 학생 코드는 이 창의 메모리에만 있고 브라우저 저장소에 남지 않습니다. 창을 닫으면 사라집니다.
