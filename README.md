# 교육과정 편성 프로그램

교육과정 편제표를 편성하고 학생별 신청 명단 엑셀을 읽어 수강 신청 확인서와 과목별 집계표를 만드는 브라우저용 웹앱입니다. 확인서는 선택군, 과목명, 학점, 과목 수와 총학점을 표시합니다.

## 실행

1. `index.html`을 최신 Chrome 또는 Microsoft Edge에서 엽니다.
2. 2단계(`학년별 수강신청`)에서 차수(1차/2차/3차)를 선택한 뒤 해당 차수의 학생별 신청 명단 엑셀을 불러옵니다. 1차 결과를 보관한 채 2차·3차를 추가로 불러올 수 있으며, 차수 탭으로 전환해 비교할 수 있습니다. 형식 확인에는 가상 학생만 포함된 `예시 엑셀 다운로드`를 사용할 수 있습니다.
3. 불러온 데이터(차수별 명단·폐강 확정 포함)는 브라우저 저장소에 자동 보관되어 새로고침 후에도 유지됩니다. 필요하면 `불러온 데이터 초기화` 버튼으로 전체 초기화할 수 있습니다.
4. 왼쪽 `업무 흐름도`에서 작업 단계를 선택합니다. 단계는 실제 수강신청 절차 순서입니다.

## 업무 흐름 (10단계)

1. **교육과정 편제표 작성**: `저장된 교육과정 불러오기`와 `편제표 불러오기`로 각 .xlsx 파일을 불러옵니다. 편제표는 헤더(과목명/세부과목 + 기준·운영 학점 또는 시수)를 자동 인식하고, 인식이 안 되는 구조라도 표 레이아웃에서 과목 행을 만들어 표시합니다. 저장된 교육과정 목록은 과목명·교과군·유형 검색으로 과목을 찾을 수 있습니다. 편제표는 데이터 영역의 첫 행부터 마지막 행까지 빈 행과 열을 포함해 표시하므로 중간 내용이 생략되지 않습니다. 편제표 필터는 한 줄로 표시되며, 학년(전체/1~3학년)·교육과정 구분(전체/학교지정/학생선택)·교과군·선택 유형(공통/일반/진로/융합)과 과목명 검색으로 필요한 내용을 좁혀 볼 수 있습니다. 선택 유형은 과목명 앞쪽의 구분 셀에서 공통/일반/진로/융합 표기를 찾아 구별합니다. 교과군 필터에서는 표기방법 안내(특목고·전문교과·고시외·교과특성화학교 과목 표기 및 교차집중 표기 안내 포함), 2026학년도 안내, 이수학점 소개, 창의적 체험활동, 학기별 총 이수학점 항목을 제외합니다. 교차집중 표기 `↔`는 필터 검색 대상에서 제외됩니다. 저장된 교육과정은 아직 편제표에 편성되지 않은 과목을 위쪽에 표시합니다. 저장된 교육과정의 과목을 편제표로 드래그 앤 드롭하면 맨 아래에 붙지 않고, 교과군과 선택 유형(공통/일반/진로/융합)이 같은 마지막 과목 바로 아래에 끼워 넣습니다. 같은 교과군이 없으면 같은 선택 유형의 마지막 과목 아래에, 둘 다 없으면 마지막 과목 아래에 추가하며, 위 과목의 세로 병합(구분·교과군) 셀은 새 행까지 자동으로 늘어납니다. 직접 행을 추가하려면 편제표에서 기준 셀을 클릭한 다음 `행 추가`를 누릅니다. 선택한 행 바로 위에 빈 행이 생기며, 빈칸을 클릭해 입력하면 자동 저장됩니다. `실행취소`를 누르면 편제표의 직전 변경(셀 편집, 과목 추가, 행 추가, 초기화 또는 편제표 불러오기)을 되돌릴 수 있습니다. 각 학년의 학기별 운영 시수 합계도 편제표 위에 표시합니다. 한 과목을 여러 학기에 배정한 경우 각 학기에 운영학점 전체를 반영합니다.
2. **학년별 수강신청**: 현재 1학년은 2학년, 현재 2학년은 3학년의 **학생선택교육과정에 편제된 전체 과목**을 신청합니다. 신청 대상 과목은 편제표의 교육과정 구분과 학기별 시수에서 자동 추출하며, 교사가 체크로 제외하지 않습니다. `신청 받을 과목`에서 학년·학기별 목록을 확인하세요. 온라인 접수는 Supabase 교사 구글 로그인 후 명렬 업로드로 생성합니다(아래 설정 안내 참고). 기존 신청 결과 엑셀도 차수별로 불러올 수 있고, 차수 탭으로 전환하면 확인서·집계표가 해당 차수 데이터로 바뀝니다. 오프라인 접수는 `학생용 신청 양식 만들기`로 저장한 HTML을 배포하고 학생들의 JSON을 `신청 파일 취합하기`로 불러옵니다. 구글폼 접수는 `구글폼 생성 코드 복사`로 생성한 Apps Script를 실행한 뒤 설문 주소를 배포하고, 응답 스프레드시트의 .xlsx를 `구글폼 결과 변환하기`로 불러옵니다. 모든 방식은 같은 자동 추출 과목 기준을 사용하며 결과는 기존 확인서·집계표·폐강 검토 등에 반영됩니다. 학년이 다른 동일 이름 과목은 `(N학년)`을 붙여 구분합니다.
3. **수강신청 확인서 발급**: 현재 차수 데이터로 학생 목록에서 학생을 선택하고 학년도, 확인 날짜, 학교명을 조정한 뒤 `현재 학생 인쇄` 또는 `검색 결과 전체 인쇄`로 확인서를 출력합니다(인쇄 창에서 PDF 저장 가능). 신청 차수 표기는 현재 차수를 따라갑니다.
4. **수강신청 집계표 생성**: 회의용 집계표입니다. 신청 인원이 개설 기준보다 적은 과목은 **폐강 예정**으로 붉게 표시되고, 상단에 폐강 예정 과목 수가 요약됩니다. `집계표 엑셀 다운로드`로보냅니다.
5. **폐강 검토 및 2차 수강신청**: 1차 결과 기준으로 학년별 과목의 신청 인원·개설기준·자동 판정(폐강 예정/개설 가능)을 보고, 과목별로 개설/폐강/미정을 확정합니다. 이후 2단계에서 2차 명단을 불러옵니다.
6. **2차 수강신청 확인서 발급**: 3단계와 같은 확인서 화면이 2차 데이터로 자동 전환되어 표시됩니다.
7. **개설/폐강 과목 확정**: 2차 결과 기준으로 개설/폐강을 최종 확정합니다.
8. **3차 수강신청 대상자**: 최종 폐강 확정 과목을 신청한 학생 명단(학년/반/번호/이름/폐강 과목)을 표시하고 엑셀로보냅니다. 2차 데이터가 있으면 2차 기준, 없으면 1차 기준으로 추출합니다. 3차 결과 파일은 2단계에서 3차를 선택해 불러옵니다.
9. **시간표용 그룹화**: 선택과목 그룹명을 직접 추가/삭제하고, 각 과목 카드를 그룹 상자로 **드래그 앤 드롭**해 배치합니다. 화면은 `그룹 추가` → `미분류 과목(가로 배열)` → `생성된 과목군` 순서로 구성됩니다. 과목은 처음에 `미분류` 그룹에서 시작하며, 과목명 기준 자동 그룹 분류는 하지 않습니다. `Shift+클릭` 범위 선택과 `Ctrl/Cmd+클릭` 다중 선택 후 일괄 이동을 지원합니다. 이 분류는 확인서의 선택군 표기, 집계표, 다운로드 엑셀에 동일하게 적용됩니다.
10. **시간표 작성**: 시간표 편성 화면을 확장할 수 있도록 준비된 단계입니다.

## 집계 계산

학년·반별 학생 수와 과목별 신청 표시를 이용해 신청 인원을 셉니다. 학급당 기준 인원은 해당 학년 재학생 수를 명단에 있는 반 수로 나누어 계산합니다. 개설 기준(기본 90%)과 분반 기준(기본 110%)은 화면에서 조정할 수 있으며, 분반 기준으로 과목별 추천 학급수를 계산합니다. 집계표의 과목별 `개설 학급수` 칸은 0 이상의 정수로 직접 수정할 수 있으며, 수정한 값에 맞춰 총 학급수와 학급당 학생수를 다시 계산하고 다운로드 엑셀에도 반영합니다.

다운로드 엑셀 양식: 학년마다 별도 시트(예: `3학년(현2학년)`)로 나누어보내 학년을 구분합니다. 각 시트에는 학년 제목(`3학년(현2학년) 수강신청결과(2차)`)과 작성일(`2026.9.` 형식)을 맨 위에 표시하고, 그 아래 총학생수·학급당 학생수·개설기준(노란색 강조)·분반기준 표를 둡니다. 학기별로 과목을 6개씩 한 묶음(가로 열)으로 나누어 인원 수·인원수/분반기준·개설 학급수·학급당 학생수를 표로 배치하며, 마지막 열의 `총 학급수`는 학기 전체 합계를 하나의 세로 병합 셀로 표시하고, 첫 학기 표 옆에는 총학생수(예: 307.0)를 병기합니다.

`과목 분류` 탭에서 선택과목 그룹명을 직접 추가/삭제하고, 각 과목 카드를 그룹 상자로 **드래그 앤 드롭**해 배치할 수 있습니다. 화면은 `그룹 추가` → `미분류 과목(가로 배열)` → `생성된 과목군` 순서로 구성됩니다. 과목은 처음에 `미분류` 그룹에서 시작하며, 과목명 기준 자동 그룹 분류는 하지 않습니다. `Shift+클릭` 범위 선택과 `Ctrl/Cmd+클릭` 다중 선택 후 일괄 이동을 지원합니다. 이 분류는 확인서의 선택군 표기, `수강신청 결과` 탭 집계, 다운로드 엑셀에 동일하게 적용됩니다.

## 엑셀 형식

### Supabase 온라인 수강신청 (권장)

교사마다 Apps Script를 만들 필요 없이 공통 Supabase 서버를 사용합니다. 학생은 교사가 배포하는 **학교·차수별 `#event=...` 링크**에서 **6자리 숫자 코드**를 입력합니다. 앞자리 0도 포함해 여섯 자리를 그대로 입력하세요. 기존 32자리 코드는 `#student` 공통 입구에서도 사용할 수 있습니다.

신청 과목은 **편제표의 학생선택교육과정 중 학생의 진급 학년에 편제된 과목(공동교육과정·소인수 제외)**으로 자동 결정됩니다. 현재 1학년은 2학년, 현재 2학년은 3학년 과목을 신청합니다. 학교지정교육과정과 과목 행에 `공동` 또는 `소인수`가 표시된 과목은 제외하며 교사가 과목을 체크해 제외하지 않습니다. 병합 셀의 안내 표기도 검사합니다. 학기 시수가 빈칸·0·대시인 곳은 편제된 학기로 보지 않습니다. 이 기준은 Supabase·오프라인 양식·구글폼·기존 Apps Script에 공통 적용되며 과거에 저장된 제외 체크는 무시합니다. 변경 전에 이미 생성한 서버 신청의 과목은 바뀌지 않으므로 제외 기준을 적용하려면 새 신청을 생성해야 합니다. 기존 신청 결과 취합은 제외 대상 과목도 계속 읽을 수 있습니다.

학생 화면에는 `물리학 실험(융합)`, `경제(진로)`, `수학(일반)`처럼 과목명 옆에 편제표의 선택과목 분류를 함께 표시합니다. 분류 정보가 없는 과목에는 임의 분류를 붙이지 않습니다. 표시만 변경하며 저장·취합에 쓰는 과목명은 그대로 유지합니다. 별도의 SQL 업데이트는 필요 없습니다.

`세부과목` 머리글이 분류·과목명 열에 걸쳐 병합된 편제표도 지원합니다. 과목명 셀에 쉼표로 나열한 과목은 개별 신청 과목으로 분리하며, 같은 학년의 같은 과목이 여러 학기에 편제되면 학기를 합칩니다(새 Supabase 신청은 학기별 별도 선택으로 구성). 병합 셀에 적힌 학년·학기도 읽지만 `공동`·`소인수` 표기가 있으면 신규 신청에서는 제외합니다. 실제 학기 시수나 학년·학기 안내가 없는 과목에는 학기를 임의 배정하지 않습니다.

**서비스 운영자 최초 설정**

1. 신규 설치는 Supabase **SQL Editor → New query**에서 `supabase/setup.sql`, 이어서 **`supabase/upgrade-codes-history.sql`**을 각각 한 번 실행합니다. 기존 설치는 **업데이트 파일만** 실행하세요. 기존 명렬과 결과를 유지하면서 6자리 코드·이력·롤백 기능을 추가합니다. 설치 SQL은 반복 실행하지 마세요.
2. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트를 생성하거나 선택합니다. **Google Auth Platform**의 Branding·Audience·Data Access에서 앱 이름·지원 이메일·대상 사용자를 설정합니다. 여러 학교 교사가 사용한다면 Audience는 **External**로 설정하고, 테스트 상태에서는 로그인할 구글 계정을 Test users에 추가합니다. 기본 프로필·이메일·openid 범위만 사용하며 구글드라이브 권한은 요청하지 않습니다.
3. **Google Auth Platform → Clients → Create client**에서 **Web application** 유형의 OAuth 클라이언트를 생성합니다. Authorized JavaScript origins에 `https://aks-sci-lab.github.io`를, **Authorized redirect URIs**에 **`https://hapfkdkbhnqpfjdepozv.supabase.co/auth/v1/callback`**을 추가합니다. 학생 웹사이트 주소가 아닌 Supabase 콜백 주소를 넣어야 합니다.
4. Supabase **Authentication → Sign In / Providers → Google**에서 Google 제공자를 활성화하고 위 클라이언트의 **Client ID와 Client secret**을 입력해 저장합니다. Client secret은 Supabase 대시보드에만 입력하고 소스 코드·채팅에 넣지 마세요. **Authentication → URL Configuration**의 Site URL과 Redirect URLs에 **`https://aks-sci-lab.github.io/curriculum-planner/`**을 지정합니다. SMTP나 Email Templates 수정은 필요 없습니다. 다른 게시 주소를 사용한다면 해당 주소도 정확히 허용 목록에 등록하세요.
5. `index.html`과 `supabase-client.js`를 함께 웹사이트에 게시합니다. 현재 프로젝트 URL과 **publishable 공개 키**는 클라이언트에 설정되어 있습니다. secret/service_role 키는 브라우저에 넣지 않습니다.
6. 가상 명렬로 교사 로그인 → 신청 생성 → 학생 신청 → 마감 → 결과 다운로드를 확인한 후 실제 학생 정보를 등록합니다. 학교 개인정보 처리 기준, 서버 리전, 보관기간, 이용 규모·요금·메일 할당량을 확인하세요.

**교사 사용**

1. 편제표를 불러오고 자동 추출된 학생선택교육과정 과목·현재 차수·학교명·학년도를 확인합니다.
2. 2단계의 `온라인 수강신청 · Supabase`에서 `구글로 로그인`을 누르고 계정을 선택합니다. 같은 탭에서 사이트로 돌아오면 로그인됩니다. 로그인 토큰은 메모리에만 유지되므로 새로고침하거나 탭을 닫으면 다시 로그인해야 합니다. 로그인 왕복 중 임시 PKCE 확인값만 sessionStorage에 저장하고 완료·실패 시 삭제합니다.
3. `학생 명렬 업로드 · 수강신청 생성`으로 .xlsx를 업로드합니다. `학년 / 반 / 번호 / 이름` 머리글을 사용하며 `성명`, `학생명`, `출석번호` 및 `1학년`·`2학년` 시트명도 지원합니다. 현재 1·2학년 학생의 다음 학년 과목만 신청합니다.
4. 학생 코드 JSON이 생성 직후 저장됩니다. 코드 원문은 데이터베이스에 저장하지 않아 다시 조회할 수 없으므로 파일을 보관하세요. `학생 코드 메일머지 출력창`에서 전체 또는 반별로 학생별 안내문을 미리 보고 인쇄/PDF 저장할 수 있습니다. 나중에는 `저장한 코드 파일로 출력`을 사용하세요. 안내문은 학생당 한 페이지이며 이름·학년·반·번호·신청 링크·코드를 포함합니다. 분실 또는 기존 긴 코드 전환은 `전체 학생 코드 재발급`을 사용합니다. **모든 기존 코드는 무효화**되며 새 코드를 전체 학생에게 전달해야 합니다. 신청 결과는 유지됩니다. 서버 응답이 끊기면 다시 업로드하기 전에 목록을 새로고침하여 이미 생성됐는지 확인하세요.
5. `내 수강신청` 목록에서 마감·재개·결과 저장·영구 삭제를 관리합니다. 업로드할 때마다 새 신청이 생성되므로 같은 신청을 중복 업로드하지 마세요. 결과 JSON은 기존 `신청 파일 취합하기`에서 같은 차수로 불러옵니다. 기존 결과와 합치는 것이 아니라 현재 차수 결과를 대체합니다.

**학생 사용**

학교·차수 신청 링크 → 6자리 코드 입력 → 본인 정보·학교·차수 확인 → 과목 선택 → 신청 저장. 같은 코드로 재접속하면 조회·수정할 수 있으며 마감 후 수정은 서버에서 차단됩니다. 6자리 코드는 공통 학생 입구가 아닌 학교별 링크에서 사용하며 별도 추측 방지 제한은 포함하지 않습니다.

**신청 로그와 롤백**

**교과별 선택 그룹과 반복 인쇄**

**편제표 색상·학기별 그룹**

신규 기능 사용 전 기존 설치는 `supabase/upgrade-semester-groups.sql`을 한 번 실행합니다(선택 그룹 업데이트 이후). 학기 열 셀의 직접 배경색(RGB·테마·인덱스 색)을 읽어 **같은 진급 학년·같은 학기·같은 색**의 과목을 그룹화합니다. 조건부 서식의 표시 색은 읽지 않습니다. 흰색·채우기 없음은 학기별 미분류로 두고 직접 배치할 수 있습니다. 이전에 업로드한 편제표는 색상 정보를 저장하지 않았으므로 다시 업로드하세요.

학년·학기 탭에서 그룹 카드를 가로로 나누어 편집하고, 카드 내부는 필요한 경우 스크롤합니다. 다른 학기의 그룹은 이동 대상에 나타나지 않고 서버에서도 혼합을 거부합니다. 그룹명과 선택 수는 직접 지정합니다. 색상 그룹도 편집·삭제·재배치할 수 있으며 `편제표 색상으로 다시 구성`은 현재 배치·선택 수를 초기화합니다. 두 학기에 있는 동일 과목은 온라인 신청에서 `(1학기)`·`(2학기)`를 붙여 별도 선택으로 처리합니다. 새로 생성하는 신청에 적용되며 기존 서버 신청은 자동 변경하지 않습니다.

신규 설치는 setup → upgrade-codes-history → upgrade-selection-groups → upgrade-semester-groups 순서로 실행합니다. 기존 설치는 아직 실행하지 않은 업데이트만 순서대로 한 번씩 실행합니다. 기존 서버 신청의 과목 제한은 자동 변경하지 않으며, 새 신청 생성부터 적용됩니다.

2단계는 **과목·그룹 설정 / 온라인 신청 관리 / 결과 불러오기 / 다른 신청 방식** 탭으로 전환합니다. 색상으로 구성된 그룹은 이름·배치를 직접 편집할 수 있고 **선택 수는 자동 지정하지 않습니다**. 추가 그룹명을 입력하고 `그룹 만들기`를 누른 뒤, 과목을 여러 개 체크하여 이동 대상 그룹을 선택하고 `선택 과목 일괄 이동`을 누릅니다. 과목·교과군 검색과 표시 과목 전체 선택을 지원합니다. 학년·학기별로 독립적인 그룹을 만들고 각 그룹의 정확한 선택 수(0~소속 과목 수)를 직접 입력하세요. 빈 그룹과 미지정 선택 수·미분류 과목이 있으면 신청 생성이 차단됩니다. 그룹 삭제 시 과목은 해당 학기의 미분류로 돌아오며 과목 자체를 삭제하지 않습니다. 이전 학년 단위의 로컬 그룹은 새 학기별 설정으로 가져오지 않으므로 다시 지정해야 합니다. 이미 생성된 서버 신청은 그대로 유지됩니다.

모든 편제 과목은 한 그룹에 배치해야 하며 시간표용 그룹화와 독립적입니다. 학생 화면과 서버 모두 정확한 선택 수를 검증합니다. 수동 설정은 현재 브라우저에 저장되며 다른 PC에는 자동 동기화되지 않습니다. Supabase 온라인 신청에 적용되며 기존 오프라인·구글폼 방식은 이 그룹 제한을 적용하지 않습니다.

코드 인쇄 후에도 출력창과 반 선택을 유지합니다. 같은 인쇄 버튼으로 여러 번 출력할 수 있고, 매번 인쇄 내용을 다시 생성합니다. 출력창 버튼은 재로그인 후에도 활성화됩니다. 현재 탭에 코드가 없으면 버튼이 저장한 코드 JSON 선택창을 엽니다. 파일을 불러온 뒤에는 같은 버튼으로 다시 출력할 수 있습니다. 코드 원문은 서버에서 복원할 수 없으므로 재로그인 후 저장 파일이 필요하며, 단순 재출력을 위해 코드 재발급을 하지 마세요.

`내 수강신청 → 신청 로그 · 롤백`에서 학생별 신청·수정·롤백 이력을 확인하고 JSON으로 저장할 수 있습니다. 지정한 시각 **직전**의 상태로 전체 학생 또는 선택한 학생을 복원합니다. 기록별 버튼은 서버 시각의 정확한 정밀도를 사용하고, 직접 입력은 사용자 PC의 현지 시각을 UTC로 변환합니다. 첫 신청 직전으로 복원하면 미신청 상태가 되어 결과 다운로드에서 제외됩니다. 롤백도 새 이력으로 남으며 기존 이력은 삭제하지 않습니다. 신청 코드·접수 마감 여부·편제표는 롤백하지 않습니다. 동시 신청과 롤백은 신청별 잠금으로 순서대로 처리합니다.

업데이트 이전의 변경 이력은 복원할 수 없습니다. 업데이트 시 기존 상태를 기준 스냅샷으로 저장하고 이후부터 이력을 기록합니다. 기록 시작 이전 시각·미래 시각은 거부합니다. 학생 제출 후에도 접수가 열려 있으면 다시 변경될 수 있으므로 전체 복원 전 마감하는 것을 권장합니다. 영구 삭제는 해당 신청의 명렬·신청 결과·이력까지 함께 삭제하며 복구할 수 없습니다.

**접근 권한과 데이터 보관**

교사는 본인이 생성한 신청과 로그만 관리할 수 있습니다. 공개 키로 명렬·신청·이력 테이블을 직접 읽거나 쓰는 것은 금지됩니다. 6자리 코드는 긴 코드보다 추측하기 쉬우며, 로그와 롤백은 무단 조회를 방지하지는 않습니다. 학교별 링크와 코드를 개별 전달하세요. 구글 로그인 자체는 교사 자격이나 학교 소속을 증명하지 않으며 학생은 구글 로그인 없이 개인 코드만 사용합니다.

`불러온 데이터 초기화`는 로컬 브라우저 데이터만 삭제합니다. 서버 데이터는 수강신청 목록의 `명렬·결과 영구 삭제`로 별도로 삭제해야 하며 내려받은 파일도 학교 보관 정책에 따라 정리해야 합니다. 기존 Apps Script 데이터는 자동 이전되지 않습니다.

개발 검증: `node --test tests\online-application.test.cjs`. 실제 PostgreSQL 엔진에서 SQL 접근 권한까지 검사하는 `tests\supabase.test.cjs`는 `@electric-sql/pglite`가 필요하며, 저장소 밖에 설치했다면 `PGLITE_MODULE` 환경변수에 모듈 경로를 지정해 실행합니다.

### 기존 Apps Script 방식 (이전 신청 호환용)

GitHub Pages 웹사이트는 관리자 화면과 **학교 신청 링크로 접속하는 학생 전용 화면**을 제공합니다. 학생 화면 안에 관리자 구글 계정의 Google Apps Script 신청 웹앱을 삽입하며, 명렬·신청 결과는 관리자 드라이브의 비공개 스프레드시트에 저장됩니다. 구글드라이브에 학생의 직접 접근 권한을 부여하지 않습니다.

1. 1단계에서 편제표를 불러오고, 2단계에서 신청 차수를 선택하고 자동 추출된 진급 학년 학생선택교육과정 과목을 확인합니다.
2. `학생 명렬 업로드 · 온라인 신청 설정 만들기`로 .xlsx 명렬을 선택합니다. 머리글은 `학년 / 반 / 번호 / 이름`입니다. `성명`, `학생명`, `출석번호`도 지원합니다. 여러 시트의 명렬을 합치며, 학년 열이 없으면 `1학년`, `2학년` 시트명에서 현재 학년을 읽습니다. 현재 1·2학년만 신청하며, 중복 학년·반·번호나 잘못된 값은 오류로 표시합니다.
3. 자동 저장된 `온라인_수강신청_설정.json`은 명렬·편제표의 선택된 과목·차수·학교 정보를 포함합니다. 이 단계는 기존 신청 결과를 변경하지 않습니다.
4. `온라인 신청 서버 코드(.gs)`를 내려받아 [Apps Script](https://script.google.com)의 새 프로젝트에 붙여넣습니다. `initializeCourseServer`를 실행하고 권한을 승인한 뒤 실행 로그의 관리자 키를 보관합니다.
5. `배포 → 새 배포 → 웹 앱`에서 **실행 사용자: 나 / 액세스 권한: 모든 사용자**로 배포합니다. 학교 Workspace 정책에 의해 익명 웹앱 배포가 차단될 수 있습니다. 구글 로그인 연동은 자동으로 수행되지 않으며, 관리자 계정에서 이 최초 설정이 필요합니다.
6. 배포된 `/exec` 주소 뒤에 `?admin=관리자키`를 붙여 관리자 페이지를 엽니다. 설정 JSON을 업로드하면 비공개 스프레드시트와 학생별 무작위 신청 코드가 생성됩니다. 설정은 한 번만 업로드할 수 있습니다. **학교·신청 차수마다 별도 Apps Script 프로젝트**를 사용하세요.
7. `학생별 신청 코드 저장`으로 코드 목록 JSON을 내려받습니다. 게시된 편성 웹사이트의 2단계에서 `학교 수강신청 서버 주소`에 관리자 키가 없는 `/exec` 주소를 입력하고 `학교 신청 링크 만들기`를 누릅니다. `학생 화면 열기`로 학교·차수를 확인한 뒤 링크를 복사해 배포하고, 담임교사 등이 학생에게 **본인 코드만** 개별 전달합니다. 학생은 같은 웹사이트의 학생 전용 화면에서 코드를 입력하고 본인 정보와 다음 학년 과목을 확인하여 신청합니다. 재제출하면 본인의 기존 신청만 수정됩니다.
8. 관리자 페이지에서 `신청 마감` 후 `신청 결과 저장`으로 JSON을 내려받습니다. 편성 프로그램에서 같은 차수의 `신청 파일 취합하기`로 불러오면 기존 확인서·집계표 등에 반영됩니다. 다른 차수의 결과는 오류로 표시합니다. `신청 다시 열기`로 접수를 재개할 수 있습니다.

학생용 페이지에는 전체 명렬이 포함되지 않습니다. 서버는 신청 코드에 해당하는 학생 정보만 반환하고 과목을 검증하며, 동시 제출은 잠금으로 처리합니다. 신청 코드는 소지자를 학생 본인으로 간주하는 방식이며 **학교 구글 계정 인증을 대신하지는 않습니다**. 코드 유출 시 타인이 해당 학생의 신청을 조회·수정할 수 있으므로 개별 전달하세요. 관리자 키가 포함된 주소는 전체 명렬과 결과에 접근할 수 있는 비밀번호이므로 비공개로 보관하고, 관리자 작업 후 페이지를 닫으세요.

학교 신청 링크는 웹사이트 주소의 `#apply=...` 부분에 공개 Apps Script 서버 주소만 담습니다. 관리자 키·학생 코드·명렬은 포함하지 않으며, 링크 생성 시 추가 매개변수나 다른 도메인은 거부합니다. 학생 링크에서는 관리자 화면을 숨기고 브라우저에 저장된 관리자 데이터를 복원하지 않습니다. 짧은 공용 코드만으로 학교 서버를 찾는 별도 등록 서버는 사용하지 않습니다. 학교가 전달한 링크인지 확인하고, 신청 화면이 표시되지 않으면 새 창 열기 또는 학교 관리자에게 배포 상태를 확인하세요.

**이미 배포한 Apps Script가 있다면** 새 `온라인 신청 서버 코드(.gs)`로 프로젝트 코드를 교체하고 `배포 관리 → 수정 → 새 버전`으로 업데이트해야 웹사이트 안에 학생 화면을 표시할 수 있습니다. `initializeCourseServer`를 다시 실행해도 기존 관리자 키는 유지됩니다. 기존 프로젝트의 명렬·신청 결과도 그대로 유지되므로 설정 JSON을 다시 업로드하지 마세요. 프레임 삽입은 학생 화면에만 허용하며 관리자 화면은 허용하지 않습니다. 학생 화면은 다른 웹사이트에도 삽입될 수 있으므로 학교가 배포한 주소만 사용하도록 안내하세요.

설정 JSON·학생별 코드 파일·신청 결과 파일은 개인정보를 포함하므로 GitHub나 공개 저장소에 올리지 마세요. 관리자 스프레드시트도 학생에게 공유하지 마세요. Apps Script/스프레드시트에는 구글 서비스 할당량이 적용됩니다. 기존 오프라인 학생용 HTML 양식·구글폼 방식도 계속 사용할 수 있습니다.

개발 시 `node --test tests\online-application.test.cjs`로 명렬 검증·설정 생성·학생별 신청/수정/마감·결과 취합을 검사할 수 있습니다. 테스트는 구글 서비스를 모의 구현하므로 실제 배포 후에는 가상 명렬로 신청과 결과 취합을 먼저 확인하세요.

현재 기본 입력 양식은 첨부하신 `2학년 3차 수강신청 결과 최종(9.28)` 형식입니다.

- 1행: `D열=과목`, `E열 이후=과목명`
- 2행: 보통 `A~D열=학년/반/번호/성명(또는 성명/학점)`, `E열 이후=학점`
- 3행 이후: 학생별 신청 데이터 (`1`이면 해당 과목 신청)

열 위치는 고정이 아니라 헤더명(`학년`, `반`, `번호`, `성명`) 기준으로 자동 인식합니다.

기존 엑셀 처리·오프라인 양식은 브라우저 안에서만 동작합니다. Supabase 온라인 신청은 공통 데이터베이스에, 기존 Apps Script 방식은 관리자 계정 스프레드시트에 명렬과 신청을 저장합니다. `불러온 데이터 초기화`는 현재 브라우저 데이터만 삭제하며 서버 데이터나 내려받은 파일은 삭제하지 않습니다.

## 구글 스프레드시트 연동 가능성

Supabase 온라인 신청은 직접 API로 연결됩니다. 집계표를 구글 스프레드시트로 보내는 직접 API 연동은 포함하지 않았으며 다음 두 방식으로 확장할 수 있습니다.

1. **수동 연동(가장 간단)**: 다운로드한 집계표 엑셀을 구글 스프레드시트로 가져오기
2. **자동 연동(개발 필요)**: Google Sheets API + OAuth 2.0을 붙여 `집계표를 특정 스프레드시트 탭에 자동 업데이트`

자동 연동을 구현하려면 구글 클라우드 프로젝트 생성, OAuth 동의 화면 설정, 사용자 로그인 처리, 시트 범위 매핑 규칙이 필요합니다.
