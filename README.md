# 교육과정 관리

교육과정 편제표를 편성하고 학생별 신청 명단 엑셀을 읽어 수강 신청 확인서와 과목별 집계표를 만드는 브라우저용 웹앱입니다. 확인서는 선택군, 과목명, 학점, 과목 수와 총학점을 표시합니다.

## 실행

1. `index.html`을 최신 Chrome 또는 Microsoft Edge에서 엽니다.
2. 2단계(`학년별 수강신청`)는 1차로 시작합니다. 추가 신청이 필요할 때 `차수 추가`를 눌러 2차, 3차 등을 만들고 선택한 차수에 결과를 불러옵니다. 차수별 데이터는 분리해 보관되며 차수 탭으로 전환할 수 있습니다.
3. 불러온 데이터(차수별 명단·개설 결정·확정 상태 포함)는 브라우저 저장소에 자동 보관되어 새로고침 후에도 유지됩니다. 상단 `결과 차수` 또는 2단계 `신청 결과`에서 차수를 바꿀 수 있습니다. `선택한 차수 데이터 삭제`는 해당 차수의 두 학년 결과만 삭제하며 편제표·선택 그룹·다른 차수는 유지합니다.
4. 왼쪽 `업무 흐름도`에서 작업 단계를 선택합니다. 단계는 실제 수강신청 절차 순서입니다.

일반 사용에는 Node.js나 빌드 도구가 필요하지 않습니다. `index.html`, `app.js`, `xlsx-parser.js`, `styles.css`, 기존 스크립트와 `vendor` 폴더를 함께 보관하고 `index.html`을 열면 됩니다. CSS를 수정하는 개발자는 `npm ci`와 `npm run build:css`로 Tailwind 유틸리티를 포함한 `styles.css`를 다시 생성합니다.

## 작업 대상과 저장·복원

- 상단에서 학교 학년도와 현재 작업 대상을 확인하고 `학교·학년도 설정`에서 기본 정보를 수정합니다. 1단계는 선택한 **입학연도**, 2단계는 **현재 학년 → 신청 학년**, 확인서·집계·시수 통계는 **수강신청 결과와 선택 차수**를 기준으로 표시합니다. 상단 결과 차수는 웹 신청 목록의 개별 신청을 선택하거나 변경하지 않습니다.
- `이 브라우저에 저장 완료`는 이 브라우저에 자동 저장되었다는 뜻이며 서버 백업 완료를 의미하지 않습니다. 저장 실패는 상단 경고에 계속 표시되고, 자료가 손상되거나 다른 창의 저장 내용이 바뀌면 원본을 덮어쓰지 않도록 저장을 중지합니다. `저장·복원 재시도`는 원본을 다시 읽을 수 있으므로 미저장 변경은 먼저 백업하세요.
- `파일로 백업하기`(작업 자료 백업)는 편제표 편집 자료·차수별 결과·선택 그룹을 JSON으로 내려받습니다. 저장 실패한 그룹의 메모리상 수정도 복구 가능한 경우 포함합니다. 학생 개인정보가 들어갈 수 있으므로 안전하게 보관하세요. 로그인 정보는 포함하지 않습니다. **원본 엑셀 파일과 온라인 서버 자료는 별도로 보관·백업**해야 합니다.
- `백업 파일 불러오기`(백업 복원)에서 이 앱의 작업 자료 백업 JSON을 선택하면 형식을 검사한 뒤 확인을 받아 자료를 복원하고 새로고침합니다. 백업에 없는 다른 입학연도 그룹과 온라인 서버 자료는 변경하지 않습니다. 원본 엑셀 보관소는 JSON 복원에 포함되지 않으므로 다른 브라우저에서는 원본 양식 내보내기용 엑셀을 다시 업로드해야 할 수 있습니다.
- `전체 초기화`는 이 브라우저에 저장된 모든 작업 자료(입학생별·전학년 편제표와 변경 이력, 보관된 원본 엑셀, 모든 차수의 결과·개설 결정·확정 상태, 선택 그룹, 설정)를 삭제하고 처음 상태로 되돌립니다. 먼저 백업 파일 내려받기를 권하고, 경고 확인 뒤 `초기화`를 직접 입력해야 실행됩니다. 교사 로그인 정보와 온라인 서버 자료는 지우지 않으며, 되돌릴 수 없습니다.
- 손상 원본 보호 중 `현재 자료로 저장 재개`를 누르면 기존 브라우저 저장분을 현재 화면의 자료로 교체합니다. **원본 백업을 먼저 내려받은 뒤** 사용하세요. 그룹 읽기 실패는 2단계의 별도 재시도 버튼이나 정상 백업 복원으로 해결합니다.
- 좁은 화면은 `단계 선택`으로 업무 메뉴를 열고, 편제표의 `필터·검색 펼치기`로 필터를 표시합니다. PC에서는 메뉴와 필터가 항상 표시됩니다.

### 작업 흐름 보조 기능

- **마지막 백업 표시**: 상단에 `N일 전 백업`이 보이며, 작업 자료가 있는데 백업이 없거나 24시간이 지나면 빨간색으로 표시합니다. 결과 반영·차수 확정 직후에도 백업을 권하는 안내가 한 번 뜹니다(10분에 한 번).
- **단계별 상태 배지**: 업무 메뉴의 각 단계에 `완료`·`확인`·`대기` 같은 상태가 표시됩니다. 보류 중인 이동수업·시간표 메뉴는 접어 두었습니다.
- **결과 검증에서 바로 이동**: 결과 엑셀 미리보기의 경고에서 `1단계 편제표 확인`·`과목·그룹 설정으로` 버튼으로 이동해 설정을 고친 뒤, `다시 검증`으로 파일을 다시 올리지 않고 재검증합니다.
- **새 차수 설정 이어받기**: 새 차수에 해당 학년 결과를 처음 올리면 직전 차수의 개설 학급 수·학기·그룹 설정을 과목명·학기 기준으로 이어받습니다. 개설/폐강 결정은 차수마다 새로 정합니다.
- **폐강 후 재신청 진행 표시**: 4단계에서 `폐강 확정 → 재신청 대상 확인 → 다음 차수 결과 반영` 진행 상태를 보여 줍니다.
- **확인서 인쇄**: 반 필터를 고르면 `N반 전체 인쇄 (M명)`처럼 인쇄 대상 인원이 버튼에 표시되며, 학생마다 한 장씩 인쇄됩니다.

### 배포와 자료 보관

- **저장소를 둘로 나눕니다.** 이 저장소(개발용)는 비공개로 두고, 학생이 접속하는 웹 수강신청 홈페이지는 **배포용 저장소**에서만 게시합니다. 배포용 저장소에는 `npm run build:deploy`가 만든 `dist/` 내용(화면이 불러오는 파일·`vendor`·`version.json`)만 올라가고 테스트·SQL·개발 문서는 들어가지 않습니다.
- **자동 게시**: 배포용 저장소를 만든 뒤 이 저장소 Settings → Secrets and variables → Actions에서 변수 `DEPLOY_REPO`(예: `조직/저장소이름`)와 시크릿 `DEPLOY_TOKEN`(배포용 저장소에 쓸 수 있는 토큰)을 등록하면 `main`에 합칠 때마다 `.github/workflows/publish-deploy.yml`이 테스트 후 배포용 저장소를 갱신합니다. 배포용 저장소의 Pages 주소가 바뀌므로 Supabase의 Site URL·Redirect URLs와 구글 OAuth의 승인된 JavaScript 원본에 새 주소를 추가하세요.
- **버전**: `app-version.js`의 `APP_VERSION`을 배포할 때마다 올립니다. 화면 왼쪽 위와 백업 파일에 기록됩니다. `APP_UPDATE_URL`에 배포용 저장소의 `version.json` 주소를 넣으면 로컬에서 쓰는 사본이 새 버전을 안내합니다.
- **PC 파일 자동 저장**(Chrome·Edge): `자동 저장 파일 연결`로 파일 하나를 정하면 작업 자료가 바뀔 때마다 그 파일에 저장됩니다. 브라우저 저장소를 지워도 `자료 파일 열기`로 복구할 수 있고, 파일을 USB·메일로 넘기면 담당자 인수인계도 됩니다. 브라우저를 다시 열면 `저장 허용`을 한 번 눌러야 할 수 있습니다. 파일에는 개인정보가 들어갈 수 있으니 안전한 위치에 두세요.

### FHD 화면 배치

14·15.6인치 FHD 노트북과 24인치 FHD 모니터에서 사용 가능한 화면 폭에 따라 자동 배치합니다. Windows 배율 100%·125%·150%에 해당하는 가로 1920·1536·1280px 환경을 기준으로 상단 도구와 업무 메뉴를 압축하고, 편제표 4개를 한 줄에 표시합니다. 긴 파일명은 카드에 마우스를 올리면 전체 이름을 확인할 수 있습니다.

편제표는 가로 폭 전체를 사용하며, 실제 편성이 있는 학기의 시수만 요약합니다. 변경 이력과 그룹 상세 설정은 필요할 때 펼칩니다. 표 안에서 가로·세로 스크롤을 사용하고 노트북 높이에 맞춰 표시 행 수를 조정합니다. 확인서는 왼쪽 학생 목록과 오른쪽 미리보기를 나누고, 집계·시수 통계도 입력·요약을 가로 배치합니다. 인쇄 양식과 데이터는 변경하지 않습니다.

## 업무 흐름 (5단계 + 보류 2단계)

### 편제표 과목 이동·맞교체·삭제

1단계 편제표의 **과목명**을 누르면 편성 변경 팝업이 열립니다. 같은 칸에 여러 과목이 있어도 누른 과목만 처리하며, 동일 과목이 여러 학년·학기에 있으면 경고를 확인한 뒤 **기존 편성 전체**를 변경합니다.

- **이동**: 도착 학년·학기와 편성 구분(학생선택/학교지정)을 선택합니다. 학점 기본값은 기존 총학점이며 직접 수정할 수 있습니다. 적용 전 변경 전후 학점을 확인하며, 필요한 행·학기 열은 자동으로 생성합니다.
- **맞교체**: 다른 과목명을 입력하고 자동완성 목록에서 선택합니다. 두 과목의 학년·학기·학점 편성을 서로 바꾸고, 교과와 고정된 과목 종류는 각 과목을 따라 이동합니다.
- **학생선택·학교지정 변경**: 기존 학년·학기·학점·과목 종류를 유지하고 편성 구분만 변경합니다. 학교지정으로 바꾼 과목은 수강신청 선택 목록에서 제외됩니다. 반대로 학생선택으로 바꾸면 학기별 선택 그룹을 다시 지정하세요.
- **삭제**: 선택 과목의 편성을 모두 제거합니다. 같은 칸의 다른 과목은 유지합니다.

일반·진로·융합 등 **과목 종류는 고정 분류**이며 팝업이나 원본 표에서 직접 수정할 수 없습니다. 편제표에 분류가 없으면 앱에 내장된 **2022 개정 교육과정 과목 목록(833과목)**의 분류를 사용하고, 그래도 확인되지 않으면 임의로 추정하지 않고 편성 변경을 차단합니다. 목록에 없는 과목명이나 목록과 분류가 다른 과목은 편제표에서 **빨간 점선**으로 표시됩니다(학교자율과목 ☆ 등 표기 기호는 허용).

**과목 추가** 버튼에서 기준 목록의 과목명을 자동완성으로 선택하고, 학년·학기·학점·학생선택/학교지정 구분을 지정해 추가합니다. 과목 종류와 교과군은 목록에서 자동 지정되며, 필요한 행·학기 열과 오른쪽 이수학점이 함께 반영됩니다. 목록에 없는 과목이나 이미 편성된 과목의 중복 추가는 차단합니다. 기존 과목은 과목명을 눌러 편성을 변경하세요.

수정 중에는 **초안이 자동 보관**되며 `실행취소`로 되돌릴 수 있습니다. 도착 칸이 `택n` 묶음 안이면 해당 선택과목군에 자동 연결되고, 묶음 밖으로 옮긴 과목의 선택 그룹은 새 위치에서 다시 지정해야 합니다. **새 시점으로 저장**에서 변경 사유·근거를 입력하면 전체 편제표(학점·수식·병합·그룹)를 별도 확정본으로 보존합니다. 기존 확정본을 덮어쓰거나 개수 제한으로 삭제하지 않습니다. 이력의 **이 시점으로 롤백**은 선택한 확정본을 복사해 새로운 최신 확정본을 만들며, 현재 초안 교체 전 확인을 받습니다. 과거 요약만 저장된 이력은 비교할 수 있지만 롤백할 수 없습니다. 새 업로드는 최초 확정본이 없을 때만 최초 시점으로 저장하며, 원본 교체는 초안으로 반영됩니다. 이미 생성된 온라인 신청이나 업로드된 신청 결과는 자동 변경하지 않습니다.

과목명을 눌러 **교차집중 추가 / 제거**와 학년을 선택할 수 있습니다. 나란한 1·2학기 학점을 유지하며 표시를 병합하고, 같은 과목 칸의 여러 과목에는 함께 적용합니다. 기존 보조 행을 우선 재사용하고 필요한 경우에만 학점 행 하나를 추가합니다. 제거해도 학점은 유지되며, 다시 추가할 때 기존 행을 재사용합니다. 택n 묶음 안의 과목은 먼저 묶음을 해제해야 합니다. 과목 편성 시 학년 보조 열이나 사용하지 않는 학기 열은 새로 만들지 않습니다.

**과목 삭제·이동 후 비워진 행은 자동으로 접습니다.** 기존 자료에서 과목명 없이 분류·숫자만 남은 행도 인식하며, **빈 과목 행 N개 표시 / 접기**로 확인할 수 있습니다. 같은 칸의 다른 과목, 교차집중 학점 보조행, 소계·합계·안내문은 유지합니다. 삭제한 과목의 단독 이수학점도 비우되 다른 과목과 공유하는 병합 이수학점과 택n 계산 칸은 보존합니다. 남은 과목이 택n 선택 수보다 적어지면 먼저 선택 수를 줄이도록 안내합니다. 수식 참조와 원본 양식을 보호하기 위해 실제 행 번호는 변경하지 않고, 엑셀에서도 불필요한 행을 숨깁니다(택n 표기가 있는 필수 보조행은 유지). 실행취소와 과거 확정본 롤백으로 삭제 이전 상태를 복원할 수 있습니다.

### 표 안의 변경 표시와 화면 공간

**변경된 과목명에만 은은한 음영**을 표시합니다. 비교 기준은 **마지막 확정 저장본**이며 초안 자동 보관으로 기준이 바뀌지 않습니다. 과목명으로 연결해 학년·학기·학점, 학생선택/학교지정 구분, 과목 종류·교과군, 교차집중, 택n 묶음과 수동 선택 그룹을 비교합니다. 묶음 설정을 바꾸면 그 묶음에 속한 과목들이 함께 표시됩니다. 단순한 행 위치·공백·숫자 표기 차이, 소계·합계·이수학점 재계산은 변경으로 세지 않습니다. 학점 셀·묶음 셀에는 변경 음영을 넣지 않습니다.

상세 변경 내역은 상단의 **편제표 변경 이력**에서 비교할 수 있습니다. 삭제한 과목은 삭제 개수와 이력에서 확인합니다. 새 시점 저장에 성공하면 그 시점이 비교 기준이 되어 음영이 해제됩니다. 음영은 화면 전용이며 엑셀 내보내기에 섞이지 않습니다. 전체 확정본이 없는 기존 자료는 최초 업로드 기준을 유지하다가 처음 새 시점을 저장하면 마지막 저장본 비교로 전환합니다. 요약 이력만으로 과거 전체 편제표를 추정하지 않습니다.

**상단 펼치기 / 상단 접기**로 편제표 선택 카드·파일 정보·변경 이력·업무 안내를 펼치고 접을 수 있습니다. 기본은 접힌 화면이며 선택은 자동 저장됩니다. 접힌 화면에서는 중복 제목 행을 숨기되 학년·학기 머리글은 유지하고, 필터는 **필터·검색 펼치기**, 선택 묶음 목록은 **선택 묶음 펼쳐 보기**로 열 수 있습니다. 표 높이는 실제 남은 화면 높이에 맞춰 자동 조정됩니다. 다른 편제표 선택, 원본 교체, 변경 사유·날짜 이력 저장은 상단을 펼쳐 사용하세요.

### 셀 병합·삽입과 과목군 자동 연결

**셀 선택·병합·삽입**을 켜면 표 전체에서 직사각형 범위를 드래그·Shift+클릭으로 선택할 수 있습니다. 학기 영역은 일반 화면에서도 드래그로 선택 모드를 시작합니다. 키보드는 Space/Enter와 Shift+방향키를 지원합니다. 병합된 셀을 선택하면 가로·세로 전체 범위를 포함합니다. **선택 범위 병합**은 실제 엑셀 병합 정보를 저장하며, 선택 모드와 일반 화면 모두 같은 행·열 병합으로 표시합니다.

학기 영역의 **같은 학기 세로 병합은 선택과목군**, **같은 학년 1·2학기 가로 병합은 교차집중과목군**입니다. 2열×여러 행도 가능하며 포함된 과목들을 양 학기의 동일한 교차집중 그룹으로 연결합니다. 두 경우 모두 택n·과목당 학점을 지정하며 **이수학점은 학기마다 n × 학점**으로 계산합니다. 새 병합에는 택n 전용 행이나 n개의 숫자 행이 필요하지 않습니다. 학기 밖 병합은 모양만 합치고 과목군을 만들지 않습니다. 다른 학년을 가로지르거나 학기·비학기 열을 섞는 범위, 소계·창체, 기존 병합·묶음의 일부만 선택한 범위는 차단합니다.

병합 전 값·수식은 작업 데이터에 보존하며 **셀 병합 해제**로 다시 드러납니다. 새 병합에는 셀 범위·그룹 설정을 함께 저장하고, 새로고침·새 시점 저장·실행취소·롤백에도 유지합니다. 엑셀 내보내기도 같은 범위를 실제 병합하며, 과목군의 n×학점을 합계 수식에 반영합니다. 내보낸 파일의 `선택과목군 택n · 학점` / `교차집중과목군 택n · 학점` 표기를 다시 읽으면 과목군을 복원합니다. 다만 내보낸 엑셀의 병합에 가려진 개별 원래 값까지 복원하려면 앱의 작업 데이터·확정본을 사용하세요. 기존 원본 택n+숫자 방식도 계속 해석하되, 새 병합부터 실제 셀 병합 방식으로 저장합니다.

**선택 위치에 행 삽입**은 선택한 행 위에 한 행을 넣고 병합·수식 참조를 이동합니다. **셀 삽입 · 아래로 밀기**는 선택 높이만큼 해당 열의 셀만 아래로 이동하며 다른 열은 유지합니다. 머리글 삽입, 기존 병합을 일부만 밀어 나누는 삽입은 차단합니다. 삽입은 편성 위치 자체를 바꾸므로 반영 후 학년·학기·합계를 확인하세요. 두 작업 모두 실행취소가 가능합니다.

묶음 안의 과목은 **같은 선택과목군**(예: `3-1 택5`)으로 자동 지정되어 2단계 과목·그룹 설정, 시수 요약, 편제표 내보내기에 함께 적용됩니다. 연결된 그룹은 2단계에서 잠금 표시되며 드래그로 옮기거나 선택 수를 바꿀 수 없고, 편제표의 병합 칸에서만 수정합니다. 편제표 위쪽 묶음 목록을 누르면 해당 병합 칸으로 이동합니다.

온라인 신청 관리의 **학생 화면 미리보기**는 선택한 학년의 현재 과목·그룹 설정을 실제 학생 화면으로 표시합니다. 그룹별 선택 수와 1학기 → 2학기 진행을 확인할 수 있으며, 제출해도 저장되지 않습니다. 현재 설정 미리보기는 그룹 배치·선택 수 설정을 완료한 뒤 사용하세요. 생성한 신청 목록의 같은 버튼은 생성 당시 저장된 과목·그룹을 표시하므로 이후 로컬 설정 변경과 구분해 확인할 수 있습니다. 미리보기는 가상 학생만 표시합니다. 운영자 서버 설치 안내는 앱 화면이 아닌 이 설명서와 `supabase` 폴더에서 확인합니다.

학생 선택과목군은 편제표에 표시된 선택과목을 기준으로 2단계에서 확인·설정합니다. 학기별 과목과 셀 배경색으로 최초 그룹을 구성하며 선택 수는 교사가 지정합니다. `새 선택 그룹 추가`로 그룹을 만들고, 같은 학년·학기 안에서 과목을 그룹 카드에 드래그 앤 드롭하여 배치합니다. 미분류 영역에 놓으면 그룹에서 해제됩니다. 과목 수가 선택 수보다 적어지면 선택 수를 다시 지정해야 합니다. 삭제한 그룹의 과목은 미분류가 되며 다시 배치해야 신청을 생성할 수 있습니다. **이미 생성한 온라인 신청은 로컬 과목·그룹 변경으로 바뀌지 않습니다.** 편제표의 `택n` 표시와 배경색은 시수가 없는 과목의 학기 인식에도 사용됩니다.

2단계는 넓은 화면에서 학년·작업 탭과 그룹 편집 항목을 가로로 배치합니다. 학기별 전체 과목·그룹·미분류 수를 표시하고, 미지정 선택 수는 강조합니다. 과목명은 생략하지 않고 줄바꿈하며, 좁은 화면에서는 세로 배치와 큰 터치 영역을 유지합니다. 결과 차수의 상세 설명은 상단 `학교·학년도 설정`에서 확인할 수 있습니다.

업무 메뉴는 **편제표 관리 → 외부 수강신청 결과 반영 → 확인서 발급 → 집계·개설 확정 → 다음 학년도 시수 통계** 순서입니다. 결과 엑셀 업로드는 로그인 없이 로컬에서 처리합니다. `이동수업 반편성`과 `시간표 작성`은 업무 범위를 확인할 때까지 보류하며 구현하지 않습니다.

확인서 발급 화면은 넓은 화면에서 **왼쪽 기본정보 아래 학생목록**, **오른쪽 확인서 미리보기와 인쇄 버튼**으로 배치합니다. 좁은 화면에서는 기본정보 → 학생목록 → 확인서 순서로 세로 배치합니다.

1. **편제표와 변경 이력**: 업로드하는 편제표는 **내년도·올해 1학년·올해 2학년·올해 3학년 입학생의 3개년 편제표 4개**입니다. 현재 1학년의 수강신청은 올해 입학생 3개년 편제표의 2학년 과목을, 현재 2학년의 신청은 전년도 입학생 3개년 편제표의 3학년 과목을 기준으로 합니다. 내년도 입학생 편제표는 다음 학년도 시수 통계의 1학년 계산에 사용됩니다. **올해 전학년 편제표는 따로 업로드하지 않고** 올해 1·2·3학년 입학생의 3개년 편제표에서 각 학년 열(1학년=올해 입학생, 2학년=전년도, 3학년=전전년도)을 가져와 자동으로 만듭니다. 세 편제표를 모두 올리면 `전학년 편제표` 카드의 `만들기`가 켜지고, 원본이 바뀌면 `원본이 바뀌었습니다` 표시와 함께 `다시 만들기`로 반영합니다. 자동으로 만든 전학년 편제표는 원본과의 일치를 지키기 위해 직접 수정·병합·행 추가를 할 수 없고, 엑셀로 내려받을 수 있습니다. 전학년 편제표는 수강신청 과목 구성에 사용하지 않습니다. 학년도를 다음 해로 바꾸면 입학연도별 편제표·선택 그룹이 연도 키에 따라 이어지고, 지난 연도 자료는 삭제하지 않고 보존합니다. 업로드·편집 후 변경 이력을 저장하면 과목 추가·삭제·학점 변경·학기 이동을 비교할 수 있습니다.
   편제표의 `택n` 묶음은 위 **택n 선택과목 묶음**과 같이 선택과목군으로 자동 연결되며, 묶음에 속하지 않은 선택과목은 2단계의 `과목·그룹 설정`에서 그룹을 관리합니다. 시수가 비어 있어도 같은 학기의 `택n` 표시와 색이 일치하는 학생 선택 과목은 신청 과목으로 인식됩니다. 편제표 머리글의 `구분` 열(학교 지정/학생 선택 교육과정)은 제목 병합 행이 위에 있어도 인식합니다.
2. **수강신청 방식 선택 및 진행**: 2단계에서 `외부 프로그램 결과 취합` 또는 `웹앱으로 학생 신청 받기`를 선택합니다. 외부 모드는 현재 사용 중인 프로그램의 결과 엑셀을 미리보기·검증 후 로컬에 반영하며 로그인이 필요하지 않습니다. 웹앱 모드는 학생이 온라인 신청 링크와 개인 코드로 직접 신청하며, 교사 설정·신청 생성은 웹 게시와 교사 로그인이 필요합니다. 선택한 모드에 해당하는 작업 탭과 다음 작업 안내가 표시되고, 모드를 바꿔도 기존 결과나 웹 신청은 자동 삭제되지 않습니다.
3. **학년별 확인서 발급**: 2단계에서 선택한 차수의 데이터를 사용합니다. 왼쪽 기본정보·학생목록에서 학생을 선택하고 학년도, 확인 날짜, 학교명을 조정한 뒤 오른쪽 미리보기의 인쇄 버튼으로 출력합니다(PDF 저장 가능).
4. **집계·개설 확정**: 선택한 차수의 학생별 신청 집계를 검토하고, 과목별 개설 반 수와 개설·폐강 결정을 확인합니다. 위쪽 학년 탭(`전체 / 현 1학년 → 2학년 / 현 2학년 → 3학년`)이 집계표·개설/폐강 결정·재신청 대상자(엑셀 포함)·차수별 비교·집계표 엑셀(그 학년 시트만)에 함께 적용됩니다. 학년 탭은 화면에서만 기억하며 저장 자료에는 들어가지 않습니다. 개설·분반 기준, 반별 최대 인원(기본 34명), 내년 학급 수는 `기준 설정` 팝업에서 바꿉니다. 협의회 검토 후 차수를 확정하면 결과 교체와 개설 설정이 잠기고, 확정 시점 스냅샷이 보존됩니다. 확정·해제는 학년 탭과 관계없이 그 차수의 두 학년 전체에 적용됩니다. 수정이 필요하면 확정을 해제한 뒤 다시 검토·확정하세요.
5. **다음 학년도 시수 통계**: 다음 학년도 학급 수를 입력하고 각 학년의 해당 입학연도 편제표와 선택과목 근거 차수를 확인합니다. 지정 과목은 학급 수, 선택 과목은 확정된 신청 결과를 기준으로 계산합니다. 교과별 교사 수와 공통 과목 배분을 입력한 뒤 통계 엑셀을 내려받습니다. 시수 중복·미배분·편제표 누락은 화면의 확인 항목에서 점검합니다.
6. **이동수업 반편성 (보류)**: 업무 내용이 정리될 때까지 구현하지 않습니다.
7. **시간표 작성 (보류)**: 업무 범위 확인 전에는 수정하지 않습니다.

## 집계 계산

집계표는 한 과목을 한 행으로 보여 주며, 같은 행의 **교사 결정** 칸에서 개설/폐강을 정합니다. 교사 결정은 수동으로 지정하지 않은 과목에 한해 개설 기준 이상이면 **개설**, 기준 미달이면 **미정**으로 표시합니다. 수동 지정한 미정·개설·폐강은 기준이나 신청 인원이 바뀌어도 유지됩니다. 기준 미달만으로 폐강 확정하지 않습니다.

**상태** 칸의 기준 미달 배지는 참고 정보이며 **교사 결정**(미정/개설/폐강)과 구분해 표시합니다. 따라서 개설 기준 미달을 폐강 확정으로 오해하지 않고, 교사가 각 과목의 최종 상태를 직접 지정할 수 있습니다.

선택 그룹(택n)의 총 학급수는 **n × 그 학년 학급 수**(내년 학급 수를 입력했으면 그 값, 없으면 명단 반 수)와 같아야 합니다. 그룹 소제목에 `총 34 / 목표 33 (+1)`처럼 차이를 표시하고, `학급수 자동 조정`(그룹별·학년 전체)은 폐강 과목을 0학급으로 빼고 과목마다 반별 최대 인원을 넘지 않는 최소 학급(최소 1)에서 시작해 남는 학급을 학급당 인원이 가장 많은 과목부터 더합니다. 최소 학급 합계가 목표보다 많으면 바꾸지 않고 협의회 결정이 필요하다고 안내합니다. 조정 결과는 개설 학급수 수동 입력으로 저장되어 엑셀·확정 스냅샷·시수 통계에 그대로 쓰이며, 직전 조정 한 번은 `조정 취소`로 되돌릴 수 있습니다. 확정할 때 목표와 다른 그룹이나 최대 인원을 넘는 과목이 있으면 목록을 보여 주고 확정 여부를 묻습니다.

집계표의 `기준 미달` 배지 역시 폐강 확정이 아닙니다. 개설 기준은 1~200%, 분반 기준은 1~300%의 정수로 입력합니다. 잘못된 값에서는 집계·최종 결정 검토·엑셀 내보내기에 서로 다른 기본값을 적용하지 않고 입력 오류를 표시합니다.

2단계 **온라인 신청 관리 → 학생 선택 과목 변경**에서 해당 신청·학년의 학생을 선택해 과목을 변경할 수 있습니다. 미제출 학생도 표시하며 모든 학기의 그룹별 선택 수를 맞춰 저장합니다. 마감 후에도 신청 소유 교사는 수정할 수 있고, 서버 이력에 `teacher_edit`로 남으며 연동된 확인서·집계표에 반영됩니다. 편집 도중 학생 신청이 바뀌면 덮어쓰지 않고 다시 열도록 안내합니다. 로컬 결과 엑셀을 수정하는 기능은 아닙니다.

운영자는 기존 선택 그룹 업데이트 이후 Supabase SQL Editor에서 **`supabase/upgrade-teacher-selections.sql`**을 실행해야 합니다. 학생 인증코드나 서버 비밀 키 없이 소유 교사의 로그인 권한으로 조회·수정합니다.

### 편제표 소계와 원본 양식 내보내기

학년도 설정을 2027·2028 등으로 변경하면 업로드 카드의 입학연도와 신청 과목 연결이 자동으로 갱신됩니다. 온라인 신청의 임시 명렬·코드는 학년도와 현재 학년별로 분리해 보관하므로 이전 학년도의 명렬을 새 학년도 신청에 자동 재사용하지 않습니다. 새 학년도에는 그해 현재 학년이 적힌 명렬을 다시 업로드하세요. 기존 입학연도의 편제표는 삭제하지 않고 계속 사용할 수 있습니다.

### 온라인 학년도별 접근 만료

운영자는 기존 신청 관련 SQL 업데이트(교사 선택과목 수정 포함)를 모두 적용한 뒤 `supabase/upgrade-academic-year-access.sql`을 Supabase SQL Editor에서 **한 번** 실행합니다. 이 업데이트는 공개 신청 함수에 서버 시간 검사를 추가하므로 이후 구버전 SQL을 다시 실행해 함수를 덮어쓰지 마세요. 웹 배포만으로 운영 DB에 적용되지는 않습니다.

적용 후에는 해당 학년도 다음 해 **3월 1일 00:00, Asia/Seoul**부터 교사의 신청 목록·명렬·결과·코드·이력 조회, 수정·마감·삭제·롤백과 학생의 코드 접속·제출을 차단합니다. 기존 긴 코드와 학교 신청별 6자리 코드 모두 제한합니다. 예를 들어 2026학년도는 2027년 3월 1일 00:00부터 접근할 수 없습니다. 사용자 PC의 날짜나 화면 필터가 아니라 서버 시간과 서버에 저장된 신청 학년도로 판단합니다.

데이터와 신청 이력은 삭제하지 않습니다. 같은 계정으로 다음 학년도 신청을 생성·운영할 수 있습니다. 이미 열어둔 화면·내려받은 엑셀·브라우저에 저장된 로컬 결과는 회수하지 않으며, 그 이후의 서버 요청만 거부합니다. 운영 DB 관리자 접근은 별도이며 이 정책은 앱 이용자에게 적용됩니다.

1단계 상단에는 설정한 학년도에 맞춰 **현 1·2·3학년의 입학연도별 업로드 카드 3개**가 표시됩니다. 2026학년도에는 2026·2025·2024학년도 입학생 카드에서 각각 1~3학년 전체가 담긴 3개년 편제표를 업로드하고, 파일명과 업로드 여부를 확인할 수 있습니다. `편제표 보기`로 해당 연도의 편제표를 편집합니다. 현 1학년은 2026 입학생 편제표의 2학년 과목, 현 2학년은 2025 입학생 편제표의 3학년 과목을 신청하며, 현 3학년 편제표는 보관·편집용입니다. 필요한 입학연도의 편제표가 없으면 다른 연도의 편제표를 대신 사용하지 않습니다.

1단계의 제목·설명·불러오기·초기화·내보내기 버튼은 한 줄로 표시하며 좁은 화면에서는 가로로 스크롤합니다. 편제표의 숫자를 수정하면 원본의 `SUM` 범위 합계와 셀 참조·사칙연산 수식을 다시 계산해 표 안의 소계에 반영합니다. 병합 셀은 한 번만 계산하며 공유 수식도 읽습니다. 수식이 없는 고정 숫자 소계는 자동 계산 대상으로 추측하지 않습니다. 지원하지 않는 함수·다른 시트 참조·순환 참조는 오류를 표시하며 임의의 합계로 대체하지 않습니다.

`편제표 엑셀 내보내기`는 업로드 원본의 시트·서식·병합·열 너비·행 높이·인쇄 설정을 유지하면서 수정 내용과 추가한 행을 반영한 `_수정.xlsx`를 저장합니다. 수식은 수식으로 보존하고 Excel에서 열 때 전체 재계산하도록 설정합니다. 원본 파일은 해당 브라우저의 IndexedDB에 보관하며 서버로 보내지 않습니다. 새로고침 후에도 내보낼 수 있지만, 이 기능 추가 전에 업로드했거나 브라우저 저장소를 삭제한 경우 원본 편제표를 다시 업로드해야 합니다.

학년·반별 학생 수와 과목별 신청 표시를 이용해 신청 인원을 셉니다. 학급당 기준 인원은 해당 학년 재학생 수를 명단에 있는 반 수로 나누어 계산합니다. 개설 기준(기본 90%)과 분반 기준(기본 110%)은 화면에서 조정할 수 있으며, 분반 기준으로 과목별 추천 학급수를 계산합니다. 집계표의 과목별 `개설 학급수` 칸은 0 이상의 정수로 직접 수정할 수 있으며, 수정한 값에 맞춰 총 학급수와 학급당 학생수를 다시 계산하고 다운로드 엑셀에도 반영합니다.

다운로드 엑셀 양식: 학년마다 별도 시트(예: `3학년(현2학년)`)로 나누어보내 학년을 구분합니다. 각 시트에는 학년 제목(`3학년(현2학년) 수강신청결과(2차)`)과 작성일(`2026.9.` 형식)을 맨 위에 표시하고, 그 아래 총학생수·학급당 학생수·개설기준(노란색 강조)·분반기준 표를 둡니다. 학기별로 과목을 6개씩 한 묶음(가로 열)으로 나누어 인원 수·인원수/분반기준·개설 학급수·학급당 학생수를 표로 배치하며, 마지막 열의 `총 학급수`는 학기 전체 합계를 하나의 세로 병합 셀로 표시하고, 첫 학기 표 옆에는 총학생수(예: 307.0)를 병기합니다.

학생 선택과목군은 1단계 편제표에서 편성합니다. 2단계에서는 편제표 기준 그룹 구성과 선택 수를 확인합니다. 이동수업 반편성과 시간표 작성은 업무 범위를 확인할 때까지 보류하며, 해당 단계의 동작은 수정하지 않습니다.

## 엑셀 형식

### Supabase 온라인 수강신청 (권장)

교사마다 Apps Script를 만들 필요 없이 공통 Supabase 서버를 사용합니다. 학생은 교사가 배포하는 **학교·차수별 `#event=...` 링크**에서 **6자리 숫자 코드**를 입력합니다. 앞자리 0도 포함해 여섯 자리를 그대로 입력하세요. 기존 32자리 코드는 `#student` 공통 입구에서도 사용할 수 있습니다.

신청 과목은 **편제표의 학생선택교육과정 중 학생의 진급 학년에 편제된 과목(공동교육과정·소인수 제외)**으로 자동 결정됩니다. 현재 1학년은 2학년, 현재 2학년은 3학년 과목을 신청합니다. 학교지정교육과정과 과목 행에 `공동` 또는 `소인수`가 표시된 과목은 제외하며 교사가 과목을 체크해 제외하지 않습니다. 병합 셀의 안내 표기도 검사합니다. 학기 시수가 빈칸·0·대시인 곳은 편제된 학기로 보지 않지만, 해당 학기의 `택n` 태그와 같은 색으로 표시된 학생선택 과목은 그 학기 선택과목군에 포함합니다. 과거에 저장된 제외 체크는 무시합니다. 변경 전에 이미 생성한 서버 신청의 과목은 바뀌지 않으므로 제외 기준을 적용하려면 새 신청을 생성해야 합니다. 기존 신청 결과 취합은 제외 대상 과목도 계속 읽을 수 있습니다.

학생 화면에는 `물리학 실험(융합)`, `경제(진로)`, `수학(일반)`처럼 과목명 옆에 편제표의 선택과목 분류를 함께 표시합니다. 분류 정보가 없는 과목에는 임의 분류를 붙이지 않습니다. 표시만 변경하며 저장·취합에 쓰는 과목명은 그대로 유지합니다. 별도의 SQL 업데이트는 필요 없습니다.

개인 코드 방식은 명렬의 현재 학년으로 신청 학년을 고정합니다. **현재 1학년은 2학년 과목만, 현재 2학년은 3학년 과목만** 조회·신청할 수 있으며 학생 화면에서 학년을 바꿀 수 없습니다. 서버도 다른 학년의 과목 제출을 거부합니다.

학생 신청은 **1학기 → 2학기 → 신청 저장** 순서로 진행합니다. 1학기 그룹의 선택 수를 채워야 다음 학기로 이동하며, 이전 학기로 돌아가도 선택은 유지됩니다. 마지막 단계에서 모든 학기의 신청을 한 번에 저장합니다. 한 학기만 있는 신청은 해당 학기에서 바로 저장하고, 학기 미정 또는 이전 방식의 혼합 그룹은 마지막 단계에 표시합니다. 마감된 신청도 학기를 전환하며 기존 선택을 확인할 수 있습니다.

같은 과목이 두 학기에 개설되어도 학생은 **한 학기에만 신청**할 수 있습니다. 앞 학기에서 선택한 과목의 다른 학기 선택지는 비활성화되며, 기존 선택을 해제하면 다시 선택할 수 있습니다. 교사 수정 화면과 서버 저장에서도 학기 표기를 제외한 동일 과목의 중복 선택을 거부합니다.

**2차 이후 재선택**

온라인 신청 관리의 `2차 이후 수강신청`에서 기준 신청과 재선택 방식을 선택하고 `다음 차수 수강신청 생성`을 누릅니다. 이전 신청을 마감하고 집계표에서 과목별 교사 최종 결정을 `폐강`으로 지정해야 합니다. 명렬을 다시 업로드하지 않고 이전 신청의 명렬·그룹·과목을 사용해 다음 번호의 차수를 생성합니다. 이전 차수 미제출 학생도 전체 학생 방식에서는 신청할 수 있으며, 폐강 대상학생 방식에서는 기존 미제출 상태를 유지합니다.

- **전체 학생 재선택**: 폐강 과목을 제외한 전체 선택지를 제공하고 모든 학생이 다시 선택합니다.
- **폐강 신청 학생만 대체 선택**: 폐강 과목 신청 학생만 대체 과목을 선택합니다. 폐강되지 않은 기존 과목은 선택 해제·변경할 수 없습니다. 대상이 아닌 학생은 기존 결과가 그대로 다음 차수에 보존되며 조회만 가능합니다.

두 방식 모두 기존 그룹별 선택 수를 유지하며, 폐강 제외 후 선택 가능한 과목 수가 부족하면 생성을 중단하고 해당 그룹을 안내합니다. 새 신청 링크·개인 코드가 발급되므로 새 코드 파일을 저장하고 재선택 대상 학생에게 전달하세요. 기존 신청과 결과는 삭제하지 않습니다. 학생별 대상 여부와 유지 과목은 서버에도 저장하므로 화면 조작이나 교사 수정으로 제한을 우회할 수 없습니다.

운영 DB에는 교사 선택과목 수정 업데이트(`upgrade-teacher-selections.sql`) 적용 후 **`supabase/upgrade-reselection.sql`을 한 번 실행**해야 합니다. 기존 학년도 접근 제한이 설치되어 있으면 그대로 유지합니다. 이 업데이트 전에는 서버 중복 방지·재선택 모드가 적용되지 않습니다. SQL 업데이트 후 새 클라이언트를 게시하세요. 기존 신청 결과를 자동으로 삭제하거나 수정하지 않으며, 기존 중복 선택은 이후 수정·저장 시 해소해야 합니다.

학생용 신청 링크에는 교사용 로그인 화면을 표시하지 않습니다. 과목 선택 화면에서 `본인 확인 → 과목 선택(학기 진행 포함) → 신청 저장` 진행 표시를 제공하며, 선택을 수정하면 완료 표시가 다시 선택 단계로 돌아갑니다. 교사 2단계에는 과목·그룹 확인부터 신청 생성, 코드 안내·결과 확인까지 해당 탭으로 이동하는 빠른 작업 안내가 있습니다.

`세부과목` 머리글이 분류·과목명 열에 걸쳐 병합된 편제표도 지원합니다. 과목명 셀에 쉼표로 나열한 과목은 개별 신청 과목으로 분리하며, 같은 학년의 같은 과목이 여러 학기에 편제되면 학기를 합칩니다(새 Supabase 신청은 학기별 별도 선택으로 구성). 병합 셀에 적힌 학년·학기도 읽지만 `공동`·`소인수` 표기가 있으면 신규 신청에서는 제외합니다. 시수가 없더라도 같은 학기 `택n` 태그와 배경색이 일치하는 학생선택 과목은 해당 선택과목군의 과목으로 인식하며, 이 색상 태그가 없는 과목에는 학기를 임의 배정하지 않습니다.

1. 신규 설치는 Supabase **SQL Editor → New query**에서 `supabase/setup.sql`, 이어서 **`supabase/upgrade-codes-history.sql`**, **`supabase/upgrade-realtime-sync.sql`**을 각각 한 번 실행합니다. 기존 설치는 두 업데이트 파일을 실행하세요. 기존 명렬과 결과를 유지하면서 6자리 코드·이력·롤백·실시간 집계 갱신을 추가합니다. 설치 SQL은 반복 실행하지 마세요.
2. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트를 생성하거나 선택합니다. **Google Auth Platform**의 Branding·Audience·Data Access에서 앱 이름·지원 이메일·대상 사용자를 설정합니다. 여러 학교 교사가 사용한다면 Audience는 **External**로 설정하고, 테스트 상태에서는 로그인할 구글 계정을 Test users에 추가합니다. 기본 프로필·이메일·openid 범위만 사용하며 구글드라이브 권한은 요청하지 않습니다.
3. **Google Auth Platform → Clients → Create client**에서 **Web application** 유형의 OAuth 클라이언트를 생성합니다. Authorized JavaScript origins에 `https://aks-sci-lab.github.io`를, **Authorized redirect URIs**에 **`https://hapfkdkbhnqpfjdepozv.supabase.co/auth/v1/callback`**을 추가합니다. 학생 웹사이트 주소가 아닌 Supabase 콜백 주소를 넣어야 합니다.
4. Supabase **Authentication → Sign In / Providers → Google**에서 Google 제공자를 활성화하고 위 클라이언트의 **Client ID와 Client secret**을 입력해 저장합니다. Client secret은 Supabase 대시보드에만 입력하고 소스 코드·채팅에 넣지 마세요. **Authentication → URL Configuration**의 Site URL과 Redirect URLs에 **`https://aks-sci-lab.github.io/curriculum-planner/`**을 지정합니다. SMTP나 Email Templates 수정은 필요 없습니다. 다른 게시 주소를 사용한다면 해당 주소도 정확히 허용 목록에 등록하세요.
5. `index.html`과 `supabase-client.js`를 함께 웹사이트에 게시합니다. 현재 프로젝트 URL과 **publishable 공개 키**는 클라이언트에 설정되어 있습니다. secret/service_role 키는 브라우저에 넣지 않습니다.
6. 가상 명렬로 교사 로그인 → 신청 생성 → 학생 신청 → 마감 → 결과 다운로드를 확인한 후 실제 학생 정보를 등록합니다. 학교 개인정보 처리 기준, 서버 리전, 보관기간, 이용 규모·요금·메일 할당량을 확인하세요.

**교사 사용**

1. 로컬 편제표 관리·외부 결과 업로드·확인서·집계·시수 통계는 로그인 없이 사용할 수 있습니다. 2단계에서 외부 모드와 웹앱 모드를 선택할 수 있습니다. 웹앱 모드에서 교사가 신청 설정·생성을 할 때만 온라인 서비스 화면에서 구글 로그인이 필요합니다. 학생은 배포된 신청 링크와 개인 코드로 신청하며 교사 로그인을 하지 않습니다.
2. 로그인 세션은 브라우저 localStorage에 저장해 새로고침 후에도 유지합니다. 클릭·키 입력·스크롤·터치 등의 사용자 활동이 **5분간 없으면 자동 로그아웃**하고 저장 세션을 삭제합니다. 서버 집계 자동 갱신은 사용자 활동으로 계산하지 않습니다. 브라우저를 닫았다가 5분 이후 다시 열어도 로그인은 만료됩니다. 공용 PC에서는 수동 로그아웃하세요. 로그인 왕복 중 임시 PKCE 확인값은 sessionStorage에 저장하고 완료·실패 시 삭제합니다.
3. `① 학생 명렬 업로드 · 신청 학년 확인`으로 .xlsx를 업로드하고 해당 학년 그룹·선택 수를 설정한 뒤 `② 그룹 설정 완료 · 수강신청 생성`을 누릅니다. `학년 / 반 / 번호 / 이름` 머리글을 사용하며 `성명`, `학생명`, `출석번호` 및 `1학년`·`2학년` 시트명도 지원합니다. 현재 1·2학년 학생의 다음 학년 과목만 신청합니다.
4. 학생 코드 엑셀이 생성 직후 저장됩니다. 코드 원문은 데이터베이스에 저장하지 않아 다시 조회할 수 없으므로 파일을 보관하세요. `학생 코드 메일머지 출력창`에서 전체 또는 반별로 학생별 안내문을 미리 보고 인쇄/PDF 저장할 수 있습니다. 나중에는 `저장한 코드 파일로 출력`을 사용하세요. 안내문은 학생당 한 페이지이며 이름·학년·반·번호·신청 링크·코드를 포함합니다. 분실 또는 기존 긴 코드 전환은 `전체 학생 코드 재발급`을 사용합니다. **모든 기존 코드는 무효화**되며 새 코드를 전체 학생에게 전달해야 합니다. 신청 결과는 유지됩니다. 서버 응답이 끊기면 다시 업로드하기 전에 목록을 새로고침하여 이미 생성됐는지 확인하세요.
5. `내 수강신청` 목록에서 마감·재개·집계표 연동·백업 결과 저장·영구 삭제를 관리합니다. 생성 버튼을 누를 때마다 새 신청이 생성되므로 중복 생성하지 마세요. 새 신청은 집계표에 자동 연동되며, 기존 신청은 `집계표 연동`을 한 번 누릅니다. 연동된 서버 제출 결과로 해당 차수 명단·집계표를 갱신하므로 JSON 재업로드는 필요하지 않습니다.

목록 조회나 집계 서버 오류는 로그인 복원과 별도로 표시합니다. 새로고침 중 목록 갱신이 실패해도 유효한 로그인은 유지되며 `새로고침` 버튼으로 목록을 다시 불러올 수 있습니다. 5분 무활동 자동 로그아웃 규칙은 그대로 적용합니다.

**학생 사용**

학교·차수 신청 링크 → 6자리 코드 입력 → 본인 정보·학교·차수 확인 → 과목 선택 → 신청 저장. 같은 코드로 재접속하면 조회·수정할 수 있으며 마감 후 수정은 서버에서 차단됩니다. 6자리 코드는 공통 학생 입구가 아닌 학교별 링크에서 사용하며 별도 추측 방지 제한은 포함하지 않습니다.

학생 화면의 하단 고정 요약에는 이번 신청의 총 학점과 그중 국어·영어·수학 학점 및 비율을 표시합니다. 이 비율은 현재 선택한 과목 학점만으로 계산하며 졸업 이수학점 충족 여부를 뜻하지 않습니다. 교과군 정보가 있으면 이를 기준으로, 없으면 표준 국·영·수 과목명으로 분류합니다.

학생 신청 링크에서는 그룹별 선택 수에 도달하면 미선택 과목이 비활성화됩니다. 선택한 과목을 해제하면 다른 과목을 선택할 수 있으며, 정확한 선택 수는 저장 시 서버에서도 검증합니다.

**온라인 신청 → 집계표 자동 연동**

온라인 결과의 선택과목 그룹명·학기·일반/진로/융합 분류는 **해당 온라인 신청에 저장된 그룹 설정과 과목 목록**을 기준으로 표시합니다. 현재 열려 있는 학년 메뉴나 브라우저의 로컬 그룹 설정으로 덮어쓰지 않으며, 각 학년의 신청 과목만 해당 학년 집계표에 표시합니다. 이 정보는 차수별 결과와 함께 저장되어 새로고침 후에도 유지됩니다.

새 신청은 생성 후 자동으로 집계표에 연동됩니다. 기존 신청은 온라인 신청 관리 목록의 `집계표 연동`을 한 번 누르세요. Supabase Realtime 연결 시 학생 제출 변경을 즉시 해당 차수의 명단·확인서·집계표에 반영합니다. 연결이 끊긴 동안에는 30초 간격으로 갱신하고, 연결 복구 시 현재 서버 결과를 다시 확인합니다. 결과 파일을 업로드할 필요가 없으며 `신청 결과 저장`은 백업용 엑셀입니다. 로그아웃하거나 페이지를 닫으면 갱신은 멈추고, 로그인 세션 복원 또는 다시 로그인하면 재개합니다. 연동 신청 ID는 교사 계정별로 저장하며, 세션은 5분 무활동 만료 규칙에 따라 브라우저에 저장합니다.

같은 학교·학년도·차수의 여러 신청을 연동해 1·2학년 결과를 함께 집계할 수 있습니다. 같은 차수에 다른 학교·학년도 신청은 함께 연동하지 못하며, 동일 학생이 여러 신청에 제출했거나 과목 설정이 충돌하면 오류를 표시하고 해당 차수 갱신을 중단합니다. 기존 로컬 명단이 있으면 첫 연동 전에 대체 여부를 확인합니다. 온라인 연동은 그 차수의 명단을 서버 결과로 대체하므로 수동 취합 데이터와 섞지 마세요. 마지막 연동을 해제해도 마지막으로 반영한 로컬 명단은 유지됩니다. 아직 제출하지 않은 학생은 집계에 포함되지 않고, 롤백으로 제출 결과가 모두 사라지면 해당 차수 명단도 비워집니다.

온라인 신청은 **1학년 → 2학년 수강신청 / 2학년 → 3학년 수강신청** 메뉴 선택 → `① 학생 명렬 업로드 · 신청 학년 확인` → 해당 학년의 그룹·선택 수 설정 → 온라인 신청 관리 탭의 `② 그룹 설정 완료 · 수강신청 생성` 순서입니다. 각 메뉴에는 해당 학년의 과목·그룹과 온라인 신청만 표시합니다. **2학년 수강신청에는 현재 1학년 명렬만, 3학년 수강신청에는 현재 2학년 명렬만 허용합니다. 다른 학년이 한 명이라도 포함되면 파일 전체를 거부하고 오류를 표시하며, 해당 학생을 조용히 제외하지 않습니다.** 학년별로 분리한 명렬을 각각 업로드하세요. 파일을 읽는 중 메뉴나 학년도가 바뀌어도 업로드를 거부합니다. 메뉴를 전환해도 다른 학년의 그룹 설정과 업로드한 명렬·방금 생성한 코드는 유지됩니다(명렬·코드 임시 보관은 로그인 중 현재 페이지에 한함). 색상으로 다시 구성하는 작업도 선택한 학년의 그룹만 초기화합니다. 이전에 만든 두 학년 통합 서버 신청은 양쪽 메뉴에 표시하며 관리 작업이 두 학년에 적용됨을 안내합니다.

`결과 불러오기`의 차수별 보관 인원·파일명은 선택한 현재 학년 기준으로 표시합니다. **선택한 학년·차수만 저장하거나 교체**하며 같은 차수의 다른 학년은 유지합니다. 결과 미리보기는 중복 좌석, 빈 선택, 편제표와 다른 과목, 다른 학년 행 등을 구분해 알려줍니다. 차수·학년·잠금 상태가 미리보기 이후 바뀌면 반영을 거부합니다. **선택한 차수 데이터 삭제는 두 학년 전체에 적용**되며 다른 차수와 편제표·선택 그룹은 유지됩니다.

신규 기능 사용 전 기존 설치는 `supabase/upgrade-semester-groups.sql`을 한 번 실행합니다(선택 그룹 업데이트 이후). 추가 차수가 필요한 기존 설치는 그 다음 `supabase/upgrade-application-rounds.sql`도 실행하세요. 학기 열 셀의 직접 배경색(RGB·테마·인덱스 색)을 읽어 **같은 진급 학년·같은 학기·같은 색**의 과목을 그룹화합니다. 조건부 서식의 표시 색은 읽지 않습니다. 흰색·채우기 없음은 학기별 미분류로 두고 직접 배치할 수 있습니다. 이전에 업로드한 편제표는 색상 정보를 저장하지 않았으므로 다시 업로드하세요.

학년·학기 탭에서 그룹 카드를 가로로 나누어 편집하고, 카드 내부는 필요한 경우 스크롤합니다. 다른 학기의 그룹은 이동 대상에 나타나지 않고 서버에서도 혼합을 거부합니다. 그룹명과 선택 수는 직접 지정합니다. 색상 그룹도 편집·삭제·재배치할 수 있으며 `편제표 색상으로 다시 구성`은 현재 배치·선택 수를 초기화합니다. 두 학기에 있는 동일 과목은 온라인 신청에서 `(1학기)`·`(2학기)`를 붙여 별도 선택으로 처리합니다. 새로 생성하는 신청에 적용되며 기존 서버 신청은 자동 변경하지 않습니다.

편제표에서 셀을 선택해 그룹을 만드는 기능은 제거했습니다. 색 없는 과목은 **2단계 → 과목·그룹 설정**에서 학년·학기별로 여러 과목을 체크해 그룹에 배치하세요. 기존 그룹 설정은 유지됩니다.

신규 설치는 setup → upgrade-codes-history → upgrade-selection-groups → upgrade-semester-groups → upgrade-application-rounds 순서로 실행합니다. 기존 설치는 아직 실행하지 않은 업데이트만 순서대로 한 번씩 실행합니다. 마지막 업데이트는 온라인 신청 차수를 1~999,999,999 범위로 확장합니다.

2단계는 **과목·그룹 설정 / 온라인 신청 관리 / 결과 불러오기** 탭으로 전환합니다. 색상으로 구성된 그룹은 이름·배치를 직접 편집할 수 있고 **선택 수는 자동 지정하지 않습니다**. 추가 그룹명을 입력하고 `그룹 만들기`를 누른 뒤, 과목을 여러 개 체크하여 이동 대상 그룹을 선택하고 `선택 과목 일괄 이동`을 누릅니다. 과목·교과군 검색과 표시 과목 전체 선택을 지원합니다. 학년·학기별로 독립적인 그룹을 만들고 각 그룹의 정확한 선택 수(0~소속 과목 수)를 직접 입력하세요. 빈 그룹과 미지정 선택 수·미분류 과목이 있으면 신청 생성이 차단됩니다. 그룹 삭제 시 과목은 해당 학기의 미분류로 돌아오며 과목 자체를 삭제하지 않습니다. 이전 학년 단위의 로컬 그룹은 새 학기별 설정으로 가져오지 않으므로 다시 지정해야 합니다. 이미 생성된 서버 신청은 그대로 유지됩니다.

모든 편제 과목은 한 그룹에 배치해야 하며 시간표용 그룹화와 독립적입니다. 학생 화면과 서버 모두 정확한 선택 수를 검증합니다. 수동 설정은 현재 브라우저에 저장되며 다른 PC에는 자동 동기화되지 않습니다.

코드 인쇄 후에도 출력창과 반 선택을 유지합니다. 같은 인쇄 버튼으로 여러 번 출력할 수 있고, 매번 인쇄 내용을 다시 생성합니다. 출력창 버튼은 재로그인 후에도 활성화됩니다. 현재 탭에 코드가 없으면 버튼이 저장한 코드 파일 선택창을 엽니다. 새 코드 파일은 엑셀이며 예전 JSON도 읽을 수 있습니다. 파일을 불러온 뒤에는 같은 버튼으로 다시 출력할 수 있습니다. 코드 원문은 서버에서 복원할 수 없으므로 재로그인 후 저장 파일이 필요하며, 단순 재출력을 위해 코드 재발급을 하지 마세요.

학생 코드 메일머지 안내문에는 **학교·차수별 신청 페이지 QR코드**도 포함됩니다. 학생은 QR코드를 스캔한 뒤 안내문에 적힌 개인 코드를 입력합니다. QR에는 학생 이름·개인 코드가 포함되지 않습니다. 미리보기·반별 인쇄·PDF 저장 모두 같은 QR를 사용하며 외부 QR 서비스 요청 없이 브라우저에서 생성합니다. QR 생성 라이브러리는 로컬 `vendor/qrcode.js`의 qrcode-generator 1.4.4(MIT, Kazuhiko Arase)이며 라이선스는 `vendor/qrcode.LICENSE`에 보관합니다.

`내 수강신청 → 신청 로그 · 롤백`에서 학생별 신청·수정·롤백 이력을 확인하고 엑셀로 저장할 수 있습니다. 지정한 시각 **직전**의 상태로 전체 학생 또는 선택한 학생을 복원합니다. 기록별 버튼은 서버 시각의 정확한 정밀도를 사용하고, 직접 입력은 사용자 PC의 현지 시각을 UTC로 변환합니다. 첫 신청 직전으로 복원하면 미신청 상태가 되어 결과 다운로드에서 제외됩니다. 롤백도 새 이력으로 남으며 기존 이력은 삭제하지 않습니다. 신청 코드·접수 마감 여부·편제표는 롤백하지 않습니다. 동시 신청과 롤백은 신청별 잠금으로 순서대로 처리합니다.

업데이트 이전의 변경 이력은 복원할 수 없습니다. 업데이트 시 기존 상태를 기준 스냅샷으로 저장하고 이후부터 이력을 기록합니다. 기록 시작 이전 시각·미래 시각은 거부합니다. 학생 제출 후에도 접수가 열려 있으면 다시 변경될 수 있으므로 전체 복원 전 마감하는 것을 권장합니다. 영구 삭제는 해당 신청의 명렬·신청 결과·이력까지 함께 삭제하며 복구할 수 없습니다.

**접근 권한과 데이터 보관**

교사는 본인이 생성한 신청과 로그만 관리할 수 있습니다. 공개 키로 명렬·신청·이력 테이블을 직접 읽거나 쓰는 것은 금지됩니다. 6자리 코드는 긴 코드보다 추측하기 쉬우며, 로그와 롤백은 무단 조회를 방지하지는 않습니다. 학교별 링크와 코드를 개별 전달하세요. 구글 로그인 자체는 교사 자격이나 학교 소속을 증명하지 않으며 학생은 구글 로그인 없이 개인 코드만 사용합니다.

`선택한 차수 데이터 삭제`는 선택한 차수의 로컬 명단·결과·분류·폐강 검토를 삭제하고 해당 차수의 자동 연동을 해제합니다. 편제표·교육과정 목록·선택 그룹·다른 차수는 유지됩니다. 서버 데이터는 수강신청 목록의 `명렬·결과 영구 삭제`로 별도로 삭제해야 하며 내려받은 파일도 학교 보관 정책에 따라 정리해야 합니다. 기존 Apps Script 데이터는 자동 이전되지 않습니다.

개발 검증: `npm test`로 전체 Node 테스트를 실행하고, `npm run build:css`로 `src/legacy.css`를 `styles.css`에 반영합니다. 실제 PostgreSQL 엔진에서 SQL 접근 권한까지 검사하는 `tests\supabase.test.cjs`는 `@electric-sql/pglite`가 필요하며, 저장소 밖에 설치했다면 `PGLITE_MODULE` 환경변수에 모듈 경로를 지정해 실행합니다.

### 수강신청 테스트봇

`test-bot.html`(상단 `자료 관리` → `수강신청 테스트봇`)은 가상 학생으로 수강신청을 시험합니다. **웹 수강신청 테스트**: 2단계 온라인 신청 관리에서 구글 로그인 후 `수강신청 자동 테스트`를 누르면 지금 편제표·선택 그룹으로 가상 학생 명렬의 `[테스트]` 수강신청을 만들고, 테스트봇 창이 학생별 접속 → 첫 접속 코드 변경 → 그룹 규칙(택 n, 1·2학기 중복 금지)에 맞는 무작위 신청 → 저장 → 다시 불러와 확인 → 교사 화면 신청·잠금 현황 대조 → 정리(기본: 신청 닫기)까지 자동으로 하고 단계별 보고서를 화면과 엑셀로 남깁니다. 이미 만든 테스트 신청은 `테스트봇으로 보내기`로 코드를 넘기거나 학생 신청 링크와 `학생별_신청코드.xlsx`를 넣어 실행합니다(확인 창에 `테스트` 입력). 틀린 코드(잠금 확인)·규칙 위반(서버 거절 확인)·재신청·인기 과목 몰림을 섞을 수 있습니다. 실제 서버에 저장되므로 실제 학생 신청에는 쓰지 마세요. 학생 코드는 봇 창 메모리에만 있고(앱과는 `postMessage`로만 주고받음) 브라우저 저장소에 남지 않습니다. **결과 파일 만들기**: 서버 없이 같은 브라우저의 앱 편제표·선택 그룹을 읽기만 해서 2단계에 올릴 가상 결과 엑셀(학생별 과목 표시 형식 또는 차수·선택과목 목록 형식)을 만들며, 미선택·택 수 위반·편제표에 없는 과목·로마숫자 표기(`미적분2`) 오류를 일부러 넣어 검증 경고를 확인할 수 있습니다.

### 데이터 파일과 결과 업로드

학생 코드·수강신청 결과·신청 로그 다운로드는 `.xlsx`로 저장합니다. 코드·번호는 엑셀 문자열 셀로 작성해 앞자리 0을 보존합니다. 결과 엑셀은 `차수 / 학년 / 반 / 번호 / 성명 / 선택과목` 형태이며, 코드 엑셀은 `신청ID / 현재학년 / 반 / 번호 / 이름 / 신청코드 / 학생링크` 형태입니다.

외부 프로그램의 `.xlsx` 결과 파일은 로그인 없이 `결과 불러오기`에서 읽습니다. 파일을 선택해도 기존 결과를 즉시 바꾸지 않습니다. 먼저 미리보기에서 차수·학년·과목 검증, 제외되는 행, 경고, 기존 결과 대비 과목별 신청 인원을 확인하고 `결과 반영`을 눌러야 저장됩니다. 선택한 학년만 교체되며 다른 학년은 보존됩니다. 학생별 결과를 합계표가 아닌 원본 엑셀에서 확인하고 업로드하세요.

업로드 과목은 학생의 진급 학년과 과목명을 기준으로 **수강신청 선택 그룹**에서 찾아 확인서·집계표의 학기와 선택군에 표시합니다. 과목명 뒤 `(1학기)`·`(2학기)` 및 선택 유형 표기도 인식합니다. 같은 이름이 두 학기 그룹에 모두 있는 경우에는 파일에 학기를 표기해야 구분할 수 있으며, 그룹에서 찾지 못하거나 중복되는 과목은 임의로 분류하지 않고 업로드 안내에 표시합니다. 기존 업로드 자료도 현재 선택 그룹과 대조하여 확인서를 표시합니다.

Apps Script 배포·서버 코드 다운로드·구글폼 생성·오프라인 신청 생성 메뉴는 제거했습니다. 기존 외부 Apps Script 배포를 이 프로그램에서 새로 생성하거나 갱신할 수 없습니다. 학생 코드·신청 결과 파일은 개인정보를 포함하므로 GitHub나 공개 저장소에 올리지 마세요.

현재 기본 입력 양식은 첨부하신 `2학년 3차 수강신청 결과 최종(9.28)` 형식입니다.

- 1행: `D열=과목`, `E열 이후=과목명`
- 2행: 보통 `A~D열=학년/반/번호/성명(또는 성명/학점)`, `E열 이후=학점`
- 3행 이후: 학생별 신청 데이터 (`1`이면 해당 과목 신청)

열 위치는 고정이 아니라 헤더명(`학년`, `반`, `번호`, `성명`) 기준으로 자동 인식합니다.

엑셀 처리는 브라우저 안에서만 동작합니다. Supabase 온라인 신청은 공통 데이터베이스에 명렬과 신청을 저장합니다. 차수 데이터 삭제는 서버 데이터나 내려받은 파일을 삭제하지 않습니다.

## 구글 스프레드시트 연동 가능성

Supabase 온라인 신청은 직접 API로 연결됩니다. 집계표를 구글 스프레드시트로 보내는 직접 API 연동은 포함하지 않았으며 다음 두 방식으로 확장할 수 있습니다.

1. **수동 연동(가장 간단)**: 다운로드한 집계표 엑셀을 구글 스프레드시트로 가져오기
2. **자동 연동(개발 필요)**: Google Sheets API + OAuth 2.0을 붙여 `집계표를 특정 스프레드시트 탭에 자동 업데이트`

자동 연동을 구현하려면 구글 클라우드 프로젝트 생성, OAuth 동의 화면 설정, 사용자 로그인 처리, 시트 범위 매핑 규칙이 필요합니다.
